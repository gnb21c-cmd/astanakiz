# 아스타나키즈 입장 데스크 — 다른 프로젝트와 공유할 내용

> 다른 프로젝트(보고 시스템 `gnb21c-cmd/report`, 아스타나 앱 `gnb21c-cmd/astana` 등) 세션은 이 문서만 읽으면 된다.
> 이 저장소에서 기능을 바꾸면 이 문서도 같이 고친다. 자세한 규칙은 `docs/OPERATION.md`, 연동은 `docs/NAVER.md` · `docs/AMANO.md` · `docs/INTEGRATION.md`.
> `gnb21c-cmd/younggu`(영구)는 별도 사업이라 공유하지 않는다.

기준: **ver.2.8** (2026-10-27)

## 1. 무엇인가
- 아스타나키즈(키즈존) **POS PC 한 대**에서 쓰는 근무자용 데스크 앱 (Windows · Electron, 1024×768 한 화면)
- 네이버 예약자 입장 · 현장 판매(결제는 OKPOS) · 열쇠 45개 관리 · 아마노 주차 할인 등록을 한 화면에서 처리
- 손님용 앱이 아니다. 문자 · 알림을 보내지 않는다. API 없이 **네이버 · 아마노 웹 화면을 숨은 창에서 대신 조작**한다
- 설치 파일: GitHub Releases `v2.X` (2.0 부터 · 그 전 `v1.0` ~ `v1.55`) (main 에 올리면 GitHub Actions 가 만듦) · 직원 메뉴얼 PDF 같이 올라감
- 체험판(설치 없이 화면만): `prototype/desk.html` → https://claude.ai/artifact/XkfdV6BDaG7AEMzRqNzSZH

**`desk-state\YYYY-MM-DD.json`** — 그날 입장 기록 (켜고 끄거나 재설치해도 남음)
```jsonc

  "b": [  // 데스크에서 입장 처리한 네이버 예약
    { "no": "1368155282", "name": "허정은", "phone": "01046740736", "slot": 840,   // slot = 예약 시각(분, 840 = 14:00)

      "naverSlot": 840 }                                                             // 네이버 원래 예약 시각(분) — slot 과 다르면 데스크에서 옮긴 예약 (1.33~)

    { "id": "w3", "phone": "01012345678", "keys": [20, 21], "keysTaken": [20, 21], "qty": 2, "enteredAt": 760, "slot": 750, "posNo": "POS-0001", "outAt": null },

  "mv": [["1368155282", 900]], // 데스크에서 시간을 옮긴 예약 [예약번호, 옮긴 시각(분)] (1.33~)

    { "id": "s8", "svc": true, "staff": true, "name": "홍길동 매니저", "phone": "", "keys": [32], "qty": 0, "of": null }  // 현장입장 창 [서비스 키] = 임직원 등 예약 없이
```

- 파일은 지우지 않음 (데스크 입장권 목록에서 2주 전까지 열쇠 번호 · 전화번호를 찾아봄). `keys` 는 지금 가진 열쇠(반납하면 빔), 어떤 열쇠를 썼는지는 `keysTaken`
- **그날 입장권 판매수** = 네이버 이용완료 장수(네이버 칸 숫자) − `x` 의 장수 + 현장 `qty` 합
- `w` 에 `extra: true` 인 줄 = 열쇠 창 [+1타임](입장권을 열쇠 수만큼 더 산 것 · `of` = 원래 손님 · `keys` 비어 있음) — 판매수에 넣음 (1.36~)
- `s` = **서비스 키** (1.43~): 판매가 아닌 열쇠. `w` 와 따로 있어 **판매수 · 시간표 인원 · 현장 구매 · 수량 자동조절 좌석에 들어가지 않음** — 보고 시스템도 세지 말 것 (열쇠를 누가 가져갔는지 찾을 때만). `of` = 연결한 네이버(`k: "n"`, `no` 예약번호) · 현장(`k: "w"`, `posNo`) 손님 — 줄 때 복사해 둬서 그 손님이 먼저 나가도 남음 · `of: null` + `staff: true` = 임직원 등(`name` · `phone` 중 하나는 있음). 초과요금 없음
- 현장 `slot` = 입장 타임(접수 시각의 바로 앞 30분 칸, 근무자가 ◀ ▶ 로 바꿀 수 있음)
- 설문조사(1.38~): `b[]` · `w[]` 의 `sv` = 그 손님이 고른 설문 번호(1~n, 제외 = 0, 없으면 대상 아님) · `sa: { "번호": 건수 }` = 그날 근무자가 [+]로 직접 더한 확인 건수(예약 없이 이벤트로 들어온 손님 등, 1.40~) — 설문 누적 · 응답 수에 더함
- **`report-outbox\survey-날짜.json`** — 설문 누적 보고 (매일 20:00 · 뒤에 숫자가 바뀌면 다시 씀 · [지금 보내기]). 통합데스크(키즈 POS)와 보고 시스템 수집(바리스타 POS)은 다른 PC 라, **보고 열쇠가 있으면 같은 글을 클라우드 설문 보고함에도** 씀 (1.41~, `PATCH …/documents/boards/{보고 열쇠}/surveyInbox/{period.from}` · `{ fields: { json: { stringValue }, at: { stringValue } } }` · 200 보냄 / 403 열쇠 · 모양 틀림 / 그 밖 실패 → 10분 뒤 다시 · report `docs/SURVEY.md`). 보고앱 주소 POST 는 1.40 에서 뺌:

```jsonc
  "options": [ { "no": 1, "label": "네이버 검색", "today": 3, "total": 12 }, … ],   // 번호별 오늘 · 기간 누적
```

```jsonc
  "base": 7,                                                           // 이벤트 전 네이버 완료 (기간 중 처음 이용완료 때의 prev) → 마일리지에서 뺄 수 = 마지막 n − base
  "st": "성공", "due": "2026-11-15" }                                   // 준 영수증 "안내" | "성공" · 다음 기한(그날 포함, 종료일에 오면 "") (함께 완료한 예약은 st 없음 · 1.37~1.38 기록은 a~e)
```

## 5. 정한 규칙 (요약 — 자세히는 `docs/OPERATION.md`)
- 열쇠 45 = 기본 40 + 유동 5 · 4인석 39
- 이용시간: 성수기(평일 · 휴일)와 비수기 휴일 = 17:30 입장까지 1시간 50분, 18:00 입장부터 무제한 · 비수기 평일 = 무제한
- 초과요금: 1:50:01부터, 2:00 정각 5,000원, 10분마다 5,000원 × 열쇠 수 (POS 에서 결제)
- 연속예약: 같은 이름 + 전화번호, 2시간 이내 간격 → 처음 입장 때 함께 이용완료, 끝 = 마지막 예약 + 1:50
- 같은 시간 나눠 한 예약: 한 번에 입장, 열쇠 합친 장수
- 추가 예약(이용 중 뒤 타임 예약): 딱 2시간 뒤 자동 연장 · 가까우면 선택 · 2:30 이상이면 당겨서 이어서 / 그대로 두기
- 이용완료 횟수 = 네이버 '완료 n'(같은 아이디의 **예약 건수**, 장수 무관). 문구는 '방문'이 아니라 "N번째 예약완료" · "네이버 예약 N번 이용완료". 10번마다 2만원 사은권
- 재방문 이벤트(1.39~, 1.37~1.38 의 a~e 를 단순하게): 시작일 ~ 종료일 동안 마일리지(입장권 누계 · 10회 사은권)는 멈추고 이벤트 안내 — 방문 뒤 20일(그날 포함) 안 재방문 = 성공 → 수제돈까스 · 그 방문일부터 다시 20일(반복), 처음 · 넘김 = 안내, 기한은 종료일까지. 끝나면 마일리지 = 네이버 완료 − 이벤트 기간 이용완료(장부의 n − base, 지난 이벤트까지) · 장부에 없는 손님은 그대로
- 네이버 판매 수량 자동조절(성수기 · 비수기 주말/휴일만): **네이버 손님만 합쳐 목표 40**(현장은 그 위로 열쇠 45개까지 · 10/24), 가까운 타임부터 · 뒤 3타임은 남는 자리만큼 · 인기 시간(기본 12:30~15:30)은 그 앞 타임이 못 가져감, 상한은 목표까지, 곧 있을 타임만 최대 13 · 나머지 기본 10, 보이는 잔여 최대 10(예약마다 줄어듦), 10분마다. **좌석(열쇠) 기준**(안의 손님은 열쇠 반납 시각까지) · 비인기 먼 타임은 예상만큼(같은 요일 지난주 70% · 3주 평균 10% · 추세 10% · 오늘 10%, 과거 없으면 지금 예약 수준 90% · 오늘 추세 10%) (1.34~ · 1.35)

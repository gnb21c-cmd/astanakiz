# 아스타나키즈 입장 데스크 — 다른 프로젝트와 공유할 내용

> 다른 프로젝트(보고 시스템 `gnb21c-cmd/report`, 아스타나 앱 `gnb21c-cmd/astana` 등) 세션은 이 문서만 읽으면 된다.
> 이 저장소에서 기능을 바꾸면 이 문서도 같이 고친다. 자세한 규칙은 `docs/OPERATION.md`, 연동은 `docs/NAVER.md` · `docs/AMANO.md` · `docs/INTEGRATION.md`.
> `gnb21c-cmd/younggu`(영구)는 별도 사업이라 공유하지 않는다.

기준: **ver.1.52** (2026-10-20)

## 1. 무엇인가
- 아스타나키즈(키즈존) **POS PC 한 대**에서 쓰는 근무자용 데스크 앱 (Windows · Electron, 1024×768 한 화면)
- 네이버 예약자 입장 · 현장 판매(결제는 OKPOS) · 열쇠 45개 관리 · 아마노 주차 할인 등록을 한 화면에서 처리
- 손님용 앱이 아니다. 문자 · 알림을 보내지 않는다. API 없이 **네이버 · 아마노 웹 화면을 숨은 창에서 대신 조작**한다
- 설치 파일: GitHub Releases `v1.X` (main 에 올리면 GitHub Actions 가 만듦) · 직원 메뉴얼 PDF 같이 올라감
- 체험판(설치 없이 화면만): `prototype/desk.html` → https://claude.ai/artifact/XkfdV6BDaG7AEMzRqNzSZH

## 3. 데이터 — POS PC 에 남는 것 (보고 시스템이 가져다 쓸 수 있음)
폴더: `%APPDATA%\아스타나키즈 입장 데스크\`

**`desk-state\YYYY-MM-DD.json`** — 그날 입장 기록 (켜고 끄거나 재설치해도 남음)
```jsonc
{
  "v": 2,
  "b": [  // 데스크에서 입장 처리한 네이버 예약
    { "no": "1368155282", "name": "허정은", "phone": "01046740736", "slot": 840,   // slot = 예약 시각(분, 840 = 14:00)
      "qty": 1, "status": "완료", "keys": [12], "enteredAt": 836, "outAt": 950,      // 입장 · 퇴장 시각(분)
      "prevDone": 8, "visitNo": 9, "visitEnd": 9,                                    // 네이버 '완료 n' (예약 이용완료 횟수)
      "proxy": false, "visitor": "",                                                 // 대리예약 · 방문자 "이름(전화번호)"
      "keyUse": { "12": 110 }, "chainHead": null, "overPaid": { "amount": 5000 },    // 열쇠별 이용시간(분) · 연속/추가 예약 대표 · 초과요금
      "keysTaken": [12], "bulkOut": false,                                           // 받은 열쇠 번호(반납해도 남음) · 일괄 반납으로 돌려받음 (1.32~)
      "naverSlot": 840 }                                                             // 네이버 원래 예약 시각(분) — slot 과 다르면 데스크에서 옮긴 예약 (1.33~)
  ],
  "w": [  // 현장 구매
    { "id": "w3", "phone": "01012345678", "keys": [20, 21], "keysTaken": [20, 21], "qty": 2, "enteredAt": 760, "slot": 750, "posNo": "POS-0001", "outAt": null }
  ],
  "x": ["1368411002"],  // '기록 삭제'(시험으로 잡힌 손님) — 판매수 · 통계에서 뺄 예약번호
  "ig": [],             // 추가 예약을 '그대로 두기'로 한 예약번호
  "mv": [["1368155282", 900]], // 데스크에서 시간을 옮긴 예약 [예약번호, 옮긴 시각(분)] (1.33~)
  "g": { "at": 1050, "keys": 19, "rest": 2 },  // 골든벨: 이 시각부터 그날 모든 손님 무제한 (1.36~, 없으면 null)
  "s": [  // 서비스 키 — 판매 아닌 열쇠 (1.43~). 판매수 · 네이버/현장 인원에 넣지 말 것
    { "id": "s7", "svc": true, "keys": [40], "keysTaken": [40], "qty": 0, "enteredAt": 830, "slot": 780, "outAt": null, "phone": "01020197975",
      "of": { "k": "n", "no": "1371163538", "name": "오유나", "keys": [6], "label": "오유나 6번" } },   // 열쇠 창 [서비스 키] = 그 손님에게 준 것 (그때 정보 복사)
    { "id": "s8", "svc": true, "staff": true, "name": "홍길동 매니저", "phone": "", "keys": [32], "qty": 0, "of": null }  // 현장입장 창 [서비스 키] = 임직원 등 예약 없이
  ]
}
```
- 파일은 지우지 않음 (데스크 입장권 목록에서 2주 전까지 열쇠 번호 · 전화번호를 찾아봄). `keys` 는 지금 가진 열쇠(반납하면 빔), 어떤 열쇠를 썼는지는 `keysTaken`
- **그날 입장권 판매수** = 네이버 이용완료 장수(네이버 칸 숫자) − `x` 의 장수 + 현장 `qty` 합
- `w` 에 `extra: true` 인 줄 = 열쇠 창 [+1타임](입장권을 열쇠 수만큼 더 산 것 · `of` = 원래 손님 · `keys` 비어 있음) — 판매수에 넣음 (1.36~)
- `s` = **서비스 키** (1.43~): 판매가 아닌 열쇠. `w` 와 따로 있어 **판매수 · 시간표 인원 · 현장 구매 · 수량 자동조절 좌석에 들어가지 않음** — 보고 시스템도 세지 말 것 (열쇠를 누가 가져갔는지 찾을 때만). `of` = 연결한 네이버(`k: "n"`, `no` 예약번호) · 현장(`k: "w"`, `posNo`) 손님 — 줄 때 복사해 둬서 그 손님이 먼저 나가도 남음 · `of: null` + `staff: true` = 임직원 등(`name` · `phone` 중 하나는 있음). 초과요금 없음
- 현장 `slot` = 입장 타임(접수 시각의 바로 앞 30분 칸, 근무자가 ◀ ▶ 로 바꿀 수 있음)
- 설문조사(1.38~): `b[]` · `w[]` 의 `sv` = 그 손님이 고른 설문 번호(1~n, 제외 = 0, 없으면 대상 아님) · `sa: { "번호": 건수 }` = 그날 근무자가 [+]로 직접 더한 확인 건수(예약 없이 이벤트로 들어온 손님 등, 1.40~) — 설문 누적 · 응답 수에 더함
- **`report-outbox\survey-날짜.json`** — 설문 누적 보고 (매일 20:00 · 뒤에 숫자가 바뀌면 다시 씀 · [지금 보내기]). 통합데스크(키즈 POS)와 보고 시스템 수집(바리스타 POS)은 다른 PC 라, **보고 열쇠가 있으면 같은 글을 클라우드 설문 보고함에도** 씀 (1.41~, `PATCH …/documents/boards/{보고 열쇠}/surveyInbox/{period.from}` · `{ fields: { json: { stringValue }, at: { stringValue } } }` · 200 보냄 / 403 열쇠 · 모양 틀림 / 그 밖 실패 → 10분 뒤 다시 · report `docs/SURVEY.md`). 보고앱 주소 POST 는 1.40 에서 뺌:
```jsonc
{ "type": "astanakiz-survey", "v": 1, "day": "2026-11-01", "sentAt": "2026-11-01 20:00",
  "question": "아스타나키즈를 어떻게 알게 되었나요", "period": { "from": "2026-11-01", "to": "2026-11-30" },
  "targets": { "naverNew": true, "walkin": false, "all": false },     // 신규고객 · 현장구매자 · 전체고객
  "options": [ { "no": 1, "label": "네이버 검색", "today": 3, "total": 12 }, … ],   // 번호별 오늘 · 기간 누적
  "excluded": { "today": 2, "total": 5 }, "answered": { "today": 10, "total": 40 } } // 제외 · 응답 수 (손님 정보 없음)
```
- `settings.json` — 프린터 · 아마노 주소(비밀번호는 Windows 암호화) · 성수기 기간 · 수량 자동조절 설정 · 톡톡 상담 목록 주소(`talkUrls`) · 현금통 단자(`drawerPin`) · 설문조사(`survey: { on, from, to, send, naverNew, walkin, all, opts: [선택지], sentDay, sentSig, last: { at, ok, why, auto, inbox: { ok, code, why } }, retry: { day, m } }` — 1.38 ~ 1.39 의 `url` 은 안 씀) · 네이버 재고 자동 오픈(`stockAuto: { on, qty, ahead, products, skip }` — 설치하면 켜짐 · 결과 `stockLast` · 성공한 날 `stockDoneDay` · 그날 써 본 때 `stockTried` — 1.52~ · 상품 번호 `stockItems: { 이름: 번호 }` — 1.53~ 목록에서 찾아 남김) · 설문 보고 열쇠(`surveyKeyEnc` — Windows 암호화, 화면에는 끝 4자리만) · 재방문 이벤트(`visitEvent: { ver: 2, on, from: "시작일", to: "종료일", days: 20, gift: "수제돈까스", tpl: ["1번 안내", "2번 성공", "제공상품"], form: null | "이벤트 기간 입장권 공통 양식", past: [{ from, to }], onAt: { day, at, done: [켜기 전 이용완료한 예약번호] } }` — past = 지난 이벤트(그 장부도 계속 마일리지에서 뺌). 1.37 · 1.38 의 `mode` · `stamp` · `rules` 는 안 씀)
- **`visit-ledger\시작일.jsonl`** + **바탕화면 `아스타나키즈-이벤트\이벤트기록_시작일.jsonl`** (같은 내용 두 곳 · 켤 때 합치고 빠진 쪽 채움, `src/ledger-store.js`) — 재방문 이벤트 손님 기록 (1.37~, 지우지 않음 · **이벤트가 끝난 뒤에도 마일리지 = 네이버 완료 − (n − base) 에 씀**). 바탕화면에는 엑셀 정리본 `이벤트참여자_시작일.csv`(손님마다 한 줄 · BOM)도. 이벤트 기간 이용완료(네이버 예약 1건)마다 한 줄 덧붙임:
```jsonc
{ "at": "2026-10-15 14:02", "day": "2026-10-15", "no": "1370988026",   // 이용완료 시각 · 날짜 · 네이버 예약번호 (같은 예약은 한 번만)
  "k": "01035598879", "name": "신혜인", "phone": "01035598879",         // 손님 (전화번호 숫자)
  "prev": 7, "n": 8,                                                   // 네이버 완료: 이 예약 전 · 이 예약 뒤
  "base": 7,                                                           // 이벤트 전 네이버 완료 (기간 중 처음 이용완료 때의 prev) → 마일리지에서 뺄 수 = 마지막 n − base
  "st": "성공", "due": "2026-11-15" }                                   // 준 영수증 "안내" | "성공" · 다음 기한(그날 포함, 종료일에 오면 "") (함께 완료한 예약은 st 없음 · 1.37~1.38 기록은 a~e)
```
- **클라우드 `boards/{보고 열쇠}/deskLive/now`** — **키즈 실시간** (1.44~ · 사장님 10/16): 통합데스크가 1분마다 · 바뀌면 5초 안에 지금 현황 글(`astanakiz-live` — 네이버 완료 · 미입장 · 잔여 + 시간 칸 · 총 판매수 · 현장 · 서비스 키 · 초과요금 · 열쇠 45칸 색 · 반납 시각 · 손님 이름 · 전화)을 덮어씀 → 보고 앱 '입장권 판매' 칸 → 세부 화면. 글 모양 · 규칙 · 화면은 **`docs/LIVE.md`** (미리보기 `prototype/live-phone.html`). 문서 하나만 덮어써서 지난 기록은 안 쌓임
- **클라우드 `boards/{보고 열쇠}/deskStats/revisit`** — **재방문 간격** (1.50~ · 사장님 10/19): 매일 20:00 일수 모음(`astanakiz-revisit` — 지난 30일 요약 · 과거 4/1 ~ 10/25 · 이벤트 10/26 ~ 걸린 일수 많은 순 7개, 손님 정보 없음)을 덮어씀 → 보고 앱 '네이버 판매 수' 세부 화면 맨 위. 글 모양 · 규칙 · 화면은 **`docs/REVISIT.md`**
- **`customer-notes.json`** — 고객 메모 (1.51~ · 사장님 10/20): 네이버 손님마다 근무자가 적는 메모 2줄 · 3자녀 · BC(블랙컨슈머) — `{ v: 1, notes: { 해시: { m, k3, bl, at } } }` (해시 = 전화번호(없으면 '이름:…') + `visitSalt`, 파일에 전화번호 · 이름 없음 · 메모 글은 그대로 · 앞 파일은 `customer-notes.bak.json`). 클라우드로 안 보냄 — 보고 시스템이 쓸 것 없음
- **`visit-history.json`** — 재방문 간격 방문 기록 (1.50~): 날마다 네이버 이용완료 손님을 전화번호(없으면 이름) + 이 PC 비밀값(`settings.json` `visitSalt`) 해시 16자로만 · `{ v: 1, days: { 날짜: { src: "naver" | "desk", k: [해시] } } }` — 이름 · 전화번호 없음

## 4. 외부 연동
| 대상 | 방식 |
|---|---|
| 네이버 스마트플레이스 예약 | 숨은 창에서 예약현황(일간) 읽기(09:50부터 매시 20 · 50분, 대리예약 방문자 · 입금대기 포함) · 이용완료 2단계 누르기 · 회차당 수량 바꾸기 · 입금대기 예약 자동 취소(지금 ~ 2시간 안). 로그인은 근무자가 직접(비밀번호 저장 안 함) |
| 네이버 톡톡 상담 | 계정 2개(아스타나키즈 · 카페아스타나)를 숨은 창에 열어 상담 목록 줄의 붉은 원(안 읽은 메시지 수)을 20초마다 더해 버튼에 표시 · 버튼 → 상담 창, X → 데스크로. 로그인은 예약과 같은 네이버 아이디 · 주소는 POS PC 에만 |
| 아마노 주차 | 숨은 창 2개(검색용 · 뒤에서 할인 등록용). 아이디 · 비밀번호는 POS PC 에만 암호화 저장 |
| 현금통 | 데스크 맨 위 [환전 오픈] → 영수증 프린터로 ESC/POS 열기 명령(ESC p) — POS 프로그램이 꺼져 있어도 |
| OKPOS | 결제는 POS 에서. 데스크는 POS 창을 앞으로 띄우고(최소화돼 있으면 복원), POS 를 최소화하면 데스크로 돌아옴 |

## 5. 정한 규칙 (요약 — 자세히는 `docs/OPERATION.md`)
- 열쇠 45 = 기본 40 + 유동 5 · 4인석 39
- 이용시간: 성수기(평일 · 휴일)와 비수기 휴일 = 17:30 입장까지 1시간 50분, 18:00 입장부터 무제한 · 비수기 평일 = 무제한
- 초과요금: 1:50:01부터, 2:00 정각 5,000원, 10분마다 5,000원 × 열쇠 수 (POS 에서 결제)
- 연속예약: 같은 이름 + 전화번호, 2시간 이내 간격 → 처음 입장 때 함께 이용완료, 끝 = 마지막 예약 + 1:50
- 같은 시간 나눠 한 예약: 한 번에 입장, 열쇠 합친 장수
- 추가 예약(이용 중 뒤 타임 예약): 딱 2시간 뒤 자동 연장 · 가까우면 선택 · 2:30 이상이면 당겨서 이어서 / 그대로 두기
- 이용완료 횟수 = 네이버 '완료 n'(같은 아이디의 **예약 건수**, 장수 무관). 문구는 '방문'이 아니라 "N번째 예약완료" · "네이버 예약 N번 이용완료". 10번마다 2만원 사은권
- 재방문 이벤트(1.39~, 1.37~1.38 의 a~e 를 단순하게): 시작일 ~ 종료일 동안 마일리지(입장권 누계 · 10회 사은권)는 멈추고 이벤트 안내 — 방문 뒤 20일(그날 포함) 안 재방문 = 성공 → 수제돈까스 · 그 방문일부터 다시 20일(반복), 처음 · 넘김 = 안내, 기한은 종료일까지. 끝나면 마일리지 = 네이버 완료 − 이벤트 기간 이용완료(장부의 n − base, 지난 이벤트까지) · 장부에 없는 손님은 그대로
- 네이버 판매 수량 자동조절(성수기 · 비수기 주말/휴일만): 어느 시각에도 안에 있는 손님이 **상한 43**을 넘지 않게, 목표 42, 한 타임 최대 13, 10분마다. **좌석(열쇠) 기준**(안의 손님은 열쇠 반납 시각까지) · 비인기 먼 타임은 예상만큼(같은 요일 지난주 70% · 3주 평균 10% · 추세 10% · 오늘 10%, 과거 없으면 지금 예약 수준 90% · 오늘 추세 10%) (1.34~ · 1.35)

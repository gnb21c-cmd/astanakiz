# 재방문 간격 — 통합데스크 → 보고 앱 (2026-10-19)

네이버 예약 손님이 **며칠 만에 다시 오는지** 본다 (사장님 10/19). 재방문 이벤트(10/26 ~)로 방문 도전이 시작되거나 성공한 뒤 다음 방문까지 걸린 일수를 이벤트 전과 견줌.

보고 앱(B) **'네이버 판매 수' 칸을 누르면 나오는 세부 화면 맨 위**에

- **한 줄 요약 — 지난 30일 재방문**: 30일 안에 온 손님마다 '마지막 방문 − 바로 전 방문' 일수 → 가장 많은 일수 · 평균 · 가운데 값 · 재방문 n명
- **아래 좌우 목록 (화면을 반으로)**: 왼쪽 **과거 4/1 ~ 10/25** · 오른쪽 **이벤트 10/26 ~ 끝날 때까지** — 재방문까지 걸린 일수, **많은 순 7개** "1위 7일 23명"

날마다의 누계는 안 남김 (사장님: 없어도 됨). **매일 20:00 (POS 가 꺼져 있지 않은 때 — 사장님 10/19) 키즈 데스크가 보내 줌** — 지금까지 모은 것을 덮어씀.

**보고 앱 쪽은 끝남 (2026-10-19, gnb21c-cmd/Report main `30b4a11`)**: 화면 `apps/view/src/screens/KidsDetail.tsx RevisitCard` · 검사 `packages/core/src/deskRevisit.ts` · 규칙 `firebase/firestore.rules deskStats` · 안내 report `docs/KIDS_REVISIT.md`. 남은 것: ① Firebase 콘솔 규칙 붙여 넣기(사장님 한 번) ② 통합데스크 1.50 설치 · 보고 열쇠 (그 뒤로는 20:00 마다 저절로)

## 무엇을 '방문'으로 세나
- **방문 = 그날 네이버 이용완료** (같은 날 여러 장 · 여러 건 = 한 번) · 현장구매(이름 · 전화번호 없음)는 안 셈
- **손님 = 전화번호** (없으면 이름) — 재방문 이벤트 장부와 같은 키
- **재방문 간격 = 같은 손님의 바로 앞 방문 → 다음 방문 일수** (10/26 → 11/2 = 7일)
- 과거 · 이벤트 목록: **두 방문이 모두 그 기간 안**일 때만 (10/20 → 10/27 처럼 경계를 넘는 재방문은 어느 쪽에도 안 셈)
- 지난 30일: 오늘 포함 30일 안에 마지막으로 온 손님마다 (바로 전 방문은 30일보다 앞이어도 됨 — 처음 온 손님은 재방문 없음)
- 7개 순위: 사람 수 많은 순, 같으면 짧은 일수 먼저
- '기록 삭제'(시험)한 예약은 안 셈

## 흐름
1. **방문 기록 (키즈 POS 에만)** — 앱 폴더 `visit-history.json` (`apps/desk/src/visit-history.js`)
   - 데스크가 입장 처리할 때마다 그날 이용완료 손님을 더함
2. **매일 20:00 (키즈 데스크 · 보고 열쇠가 있을 때)**
   1. 일수 모음(`astanakiz-revisit` — 손님 정보 없음)을 같은 **보고 열쇠**로 클라우드 **`boards/{보고 열쇠}/deskStats/revisit`** 에 덮어씀
      - 실패하면 10분 뒤 다시 · 그날 한 번 (보낸 날 `settings.json` `revisit.sentDay`) · 20:00 뒤에 켜면 켜자마자 · [지금 보내기]도 있음
   2. 이어서 **지난 방문 기록 읽기** (그날 한 번 · `revisit.fillDay`): 4/1 ~ 어제 중 네이버로 아직 안 읽은 날을 네이버 예약현황에서 **어제부터 거꾸로 하루씩** 열어 [이용완료] 칸만 읽음
      - 처음(데스크 화면이 생기기 전 4/1 ~ 10/5 포함 200일쯤)은 몇 시간 걸릴 수 있음 — 하루 몇 초 ~ 수십 초 (이용완료 손님 수만큼) · **POS 를 끄면 다음 날 20:00 에 읽은 날은 건너뛰고 이어서**
      - 다 읽은 뒤로는 날마다 **어제 하루만** 다시 확인 (데스크에서 입장 처리하지 않은 이용완료 · 20:00 뒤 손님까지)
      - 그동안 데스크 네이버 불러오기 · 이용완료는 하루씩 사이에 끼워 그대로 · 못 읽은 칸이 있던 날은 다음에 다시
   3. 새로 읽은 날이 있으면 다 읽은 뒤 **한 번 더 보냄** (20:00 것보다 새 것) · 네이버 예약현황은 오늘로 돌려놓음
3. **[지난 방문 기록 읽기]** (운영 설정 → 기타 → 보고 앱 '재방문 간격'): 20:00 을 기다리지 않고 지금 바로 읽기 — 영업 중(20:00 전)에는 한 번 더 눌러야 시작 · [멈춤] · 다시 누르면 이어서 · 다 읽으면 바로 보냄
   - 설정 줄: "기록 4/1 ~ 10/26 · 205일 · 마지막 20:00 보냄" · 읽는 중 "읽는 중 6/14 · 134 / 208일 · 방문 4210건" · 아직이면 "지난 기록은 20:00 에 저절로 읽어요"
4. 보고 앱 '네이버 판매 수' 세부 화면이 **열 때** `deskStats/revisit` 을 읽어 맨 위에 그림

## 개인정보
- `visit-history.json` 에 **이름 · 전화번호를 남기지 않음** — 전화번호(없으면 '이름:…')를 이 PC 비밀값(`settings.json` `visitSalt`, 화면에도 안 줌)과 섞은 해시 16자만 · 날짜별로
  `{ "v": 1, "days": { "2026-10-26": { "src": "desk", "k": ["3f9a…", …] }, "2026-04-01": { "src": "naver", "k": […] } } }` (`src` naver = 네이버에서 다시 읽은 날 · desk = 데스크 입장 처리로만 모인 날)
- 파일이 깨지면 `visit-history.broken-시각.json` 으로 옆에 두고 새로 (지우지 않음)
- 클라우드에 보내는 글에는 **일수 · 사람 수만** (손님 · 해시 없음)

## 보고 시스템이 할 일 (gnb21c-cmd/report 쪽)
### ① Firestore 규칙 — `firebase/firestore.rules` 의 `match /boards/{board} { … }` 안, `deskLive` 아래에 더함
```
      // 재방문 간격 (통합데스크 → 보고 앱 '네이버 판매 수' 세부 화면 맨 위) — astanakiz docs/REVISIT.md
      //   문서 하나(revisit)만 매일 20:00 덮어씀 · json = 일수 모음(astanakiz-revisit) · 손님 정보 없음
      match /deskStats/{doc} {
        allow read: if true;
        allow create, update: if doc == "revisit"
          && exists(/databases/$(database)/documents/boards/$(board)/settings/main)
          && request.resource.data.keys().hasOnly(["json", "at"])
          && request.resource.data.json is string && request.resource.data.json.size() < 20000
          && request.resource.data.json.matches("(?s)^[{].*astanakiz-revisit.*$")
          && request.resource.data.at is string && request.resource.data.at.size() < 40;
        allow delete: if isSender(board);
      }
```
- 규칙을 게시하기 전에는 통합데스크 설정에 '실패 열쇠나 모양이 틀림 (403) — 보고 시스템 규칙에 deskStats 가 있는지' 가 보임

### ② 읽기
- SDK: `getDoc(doc(db, "boards", 열쇠, "deskStats", "revisit"))` → `JSON.parse(data.json)`
- 문서가 없으면 "재방문 간격이 아직 없어요 — 키즈 POS 통합데스크 운영 설정 → 설문조사 '재방문 간격'에서 [지난 방문 기록 읽기] · 보고 열쇠를 확인해 주세요"

### ③ 화면 ('네이버 판매 수' 세부 화면 맨 위 카드)
- 맨 위 한 줄: **"지난 30일 재방문 — 가장 많은 7일 (9명) · 평균 12.4일 · 가운데 9일 · 재방문 48명"** (`recent`)
- 아래 두 칸 (반반):
  - 왼쪽 **과거 4/1 ~ 10/25** (`past`) · 오른쪽 **이벤트 10/26 ~ 2/28** (`event`, 진행 중이면 "~ 오늘 (2/28 까지)")
  - 줄마다 "**1위 7일 23명**" … 7위까지 (`top`) · 아래 작게 "재방문 n번 · n명"
  - 이벤트 시작 전(`event.started === false`)이면 "10/26 부터 모아요" · 목록이 비면 "아직 재방문 없음"
- 맨 아래 작게 "통합데스크 10/26 20:00 기준 · 기록 4/1 ~ 10/26 (205일)" — `history.from` 이 4/1 보다 늦으면 "지난 기록을 아직 다 안 읽었어요" (데스크 [지난 방문 기록 읽기])

## 일수 모음 (`deskStats/revisit` 의 `json`)
```jsonc
{ "type": "astanakiz-revisit", "v": 1, "day": "2026-10-26", "sentAt": "2026-10-26 20:00",
  "history": { "from": "2026-04-01", "to": "2026-10-26", "days": 205 },   // 방문 기록이 있는 날 (첫날 · 마지막 날 · 날 수)
  "recent": { "from": "2026-09-27", "to": "2026-10-26",                     // 지난 30일 (오늘 포함)
              "people": 120,                                                 // 30일 안에 온 손님
              "revisits": 48,                                                // 그중 전에도 온 손님 (= 간격 수)
              "mode": { "days": 7, "count": 9 },                             // 가장 많은 일수 (없으면 null)
              "avg": 12.4, "median": 9 },                                    // 평균 (소수 한 자리) · 가운데 값 (없으면 null)
  "past":  { "from": "2026-04-01", "to": "2026-10-25", "revisits": 900, "people": 400,   // 과거 (to 는 오늘을 넘지 않음)
             "top": [ { "days": 7, "count": 80 }, { "days": 14, "count": 61 }, … ] },     // 많은 순 7개
  "event": { "from": "2026-10-26", "to": "2026-10-26", "end": "2027-02-28",             // 이벤트 (to = 오늘 또는 끝난 날 · end = 종료일)
             "revisits": 0, "people": 0, "top": [] } }                                    // 시작 전이면 "started": false · 이벤트를 안 정했으면 null
```
- `revisits` = 그 기간 재방문(간격) 수 · `people` = 재방문한 손님 수 · `top[].count` = 그 일수로 다시 온 횟수(사람 수)
- 과거 = 4/1 ~ 이벤트 시작 전날 · 이벤트 = 통합데스크 방문 이벤트 탭의 시작일 ~ 종료일

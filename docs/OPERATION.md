# 아스타나키즈 운영 방식 정리

## 1. 지금 운영 방식 (앱 도입 전)

### [방법1] 네이버 예약 구매 → 매장 입장
1. 고객이 네이버에서 "아스타나키즈"를 검색해 스마트플레이스에서 날짜·시간을 골라 입장권을 구매한다.
2. 매장에 오면 근무자가 이름을 묻고, 네이버 구매자 목록에서 이름을 찾는다.
3. 예약 시간 5분 전부터 입장시키고, 현장에서 **이용완료** 버튼을 누른다.
4. 입장 처리 때 고객별 메모장에 **지급한 키 번호를 일일이 입력**하고 완료를 누른다. → 손이 많이 간다.
5. 키 반납이 늦어지면 그 키 번호를 받은 고객을 해당 시간대에서 **일일이 찾아 전화**한다.

### [방법2] 현장 구매 → 입장
- 현장에서도 입장권을 사서 입장할 수 있다.
- **예약자가 우선**이다. 만석 기준으로 자리가 남을 때만 현장 판매·입장을 한다.

## 2. 불편한 점
- 이름으로 구매자 목록을 찾는 시간
- 키 번호를 메모장에 손으로 적는 일
- 반납이 늦은 키의 주인을 찾아 전화하는 일
- 예약·현장 손님을 합친 지금 남은 자리를 한눈에 보기 어려움

## 3. 목표
아스타나 통합 앱에서 구상했던 아스타나키즈 부분을 **키즈만 따로 떼어** 이 저장소(`astanakiz`)에서 새로 만든다.
카페·퍼피 기능은 넣지 않는다. **별빛(충전 결제)은 없다.**

하나로 합칠 것:
1. 네이버 예약자 입장·퇴장 통제
2. 현장 결제 (POS 연계)
3. 열쇠 관리
4. 주차 관리 웹 입력

근무자는 **POS PC 화면(1024×768) 한 장**에서만 일한다. 네이버 예약창 · POS · 주차 웹 · 열쇠 기록 웹을 오가며 판단하는 일을 없앤다.
화면·연동 계획: `docs/INTEGRATION.md`, 체험판: `prototype/desk.html`

### 아스타나 통합 앱에서 가져올 구상
| 불편한 점 | 해결 방식 (아스타나 구상) |
|---|---|
| 이름으로 구매자 찾기 | 앱 예약 티켓 / 전화번호로 바로 찾기, 오늘 날짜로 바로 열리는 입장 화면 |
| 키 번호 수기 입력 | 근무자 **열쇠판**(키 1~45번)에서 빈 열쇠를 눌러 입장 처리 → 키 번호가 예약에 자동 연결 (4명마다 열쇠 1개) |
| 반납 지연 고객 찾기·전화 | 열쇠판에서 키를 누르면 고객·입장시간이 바로 보임. 이용시간(1시간50분)이 다 되면 고객 앱으로 퇴장·반납 알림 자동 발송 |
| 예약 우선·현장 판매 판단 | 30분 타임별 잔여 = 열쇠 수. 열쇠 40개(보유 45 − 현장 예비 5) · 인원 150명 한도. 현장 손님은 예비 열쇠부터 사용 |
| 네이버 구매자 입장 | 현장입장 등록에서 구매처(현장구매 · 네이버구매) 선택 후 전화번호·인원 입력 |
| 오지 않은 예약 정리 | 이용 종료시간이 지나도 입장 안 한 예약은 자동 이용완료 |
| 실적 보고 | 키즈입장고객실적: 네이버 · 앱 · 현장 판매 수, 추가인원, 입장료 합계 (어제 / 당월 누계) |

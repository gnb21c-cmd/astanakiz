# 아스타나키즈 운영 방식 정리

## 1. 지금 운영 방식

### [방법1] 네이버 예약 구매 → 매장 입장
1. 고객이 네이버에서 "아스타나키즈"를 검색해 스마트플레이스에서 날짜·시간을 골라 입장권을 구매한다.
2. 매장에 오면 근무자가 이름을 묻고, 네이버 구매자 목록에서 이름을 찾는다.
3. 예약 시간 5분 전부터 입장시키고, 현장에서 **이용완료** 버튼을 누른다.
4. 입장 처리 때 고객별 메모장에 **지급한 키 번호를 일일이 입력**하고 완료를 누른다. → 손이 많이 간다.
5. 키 반납이 늦어지면 그 키 번호를 받은 고객을 해당 시간대에서 **일일이 찾아 전화**한다.

### [방법2] 현장 구매 → 입장
- 현장에서도 입장권을 사서 입장할 수 있다.
- **예약자가 우선**이다. 만석 기준으로 자리가 남을 때만 현장 판매·입장을 한다.

## 2. 불편한 점
근무자가 **네이버 예약창 · POS · 주차 웹 · 열쇠 기록 웹**을 오가며 맞춰 보고 판단해야 한다.
- 이름으로 구매자 목록을 찾는 시간
- 키 번호를 메모장에 손으로 적는 일
- 반납이 늦은 키의 주인을 찾아 전화하는 일
- 예약 손님 자리를 남기고 현장에서 몇 장 팔 수 있는지 매번 판단하는 일
- 주차 웹에 차량번호를 따로 넣는 일

## 3. 새로 만드는 방향 (제로베이스)
- 아스타나 앱의 것은 **아무것도 가져오지 않는다.**
  - 별빛(충전 결제), 고객·관리자·근무자·대표자 앱 나눔, 요금·열쇠·예약 규칙 모두 처음부터 다시 정한다.
- 하나로 합칠 일
  1. 네이버 예약자 입장·퇴장 통제
  2. 현장 결제 (POS 연계)
  3. 열쇠 관리
  4. 주차 관리 웹 입력
- 근무자는 **POS PC 화면(1024×768) 한 장**에서만 일한다.

## 4. 쓰는 사람 (새로 정의)
| 누구 | 무엇으로 | 하는 일 |
|---|---|---|
| 근무자 | POS PC의 **입장 데스크** 한 화면 | 네이버 예약자 입장, 현장 결제, 열쇠 지급·반납, 주차 등록 |
| 손님 | **앱 설치 없음.** 네이버로 예약, 문자로 안내 | 예약, 반납 시간 안내 받기 |
| 사장님 | 따로 앱을 만들지 않고 시작. 필요해지면 그때 정함 | 규칙(열쇠 수·이용시간·요금) 정하기, 하루 실적 보기 |

## 5. 새로 정해야 할 규칙
체험판(`prototype/desk.html`)의 숫자는 화면을 보여 주기 위한 **임시 값**이다.

| 규칙 | 체험판 임시 값 | 정할 것 |
|---|---|---|
| 보유 열쇠 수 | 45개 | 실제 개수 |
| 열쇠 지급 단위 | 입장권 1장 = 열쇠 1개 | 한 팀에 1개인지, 인원·장수에 따라 늘어나는지 |
| 이용시간 | 1시간 50분 | 요일·시간대별로 다른지, 무제한 시간대가 있는지 |
| 현장 입장권 가격 | 16,000원 | POS에 등록된 상품·가격을 그대로 씀 |
| 예약 몇 분 전부터 입장 | 5분 | 지금 방식 그대로 |
| 반납 시간 넘기면 | 10분까지 주황, 그 뒤 빨강 · 반납 시각에 문자 자동 발송 | 문자를 언제·몇 번 보낼지 |
| 현장 판매 한도 | 예약 손님 열쇠를 먼저 남기고 남는 열쇠만큼 | 만석 기준이 열쇠 수인지, 인원·좌석 수인지 |

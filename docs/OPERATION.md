# 아스타나키즈 운영 방식 정리

## 1. 지금 운영 방식

### [방법1] 네이버 예약 구매 → 매장 입장
1. 고객이 네이버에서 "아스타나키즈"를 검색해 스마트플레이스에서 날짜·시간을 골라 입장권을 구매한다.
2. 매장에 오면 근무자가 이름을 묻고, 네이버 구매자 목록에서 이름을 찾는다.
3. 예약 시간 5분 전부터 입장시키고, 현장에서 **이용완료** 버튼을 누른다. (5분 전은 손님에게 안내하는 기준 — 근무자는 예약 당일이면 현장 상황을 보고 더 일찍도 입장시킬 수 있다. 네이버도 일찍 이용완료가 막혀 있지 않다)
4. 입장 처리 때 고객별 메모장에 **지급한 키 번호를 일일이 입력**하고 완료를 누른다. → 손이 많이 간다.
5. 키 반납이 늦어지면 그 키 번호를 받은 고객을 해당 시간대에서 **일일이 찾아 전화**한다.

### [방법2] 현장 구매 → 입장
- 현장에서도 입장권을 사서 입장할 수 있다.
- **예약자가 우선**이다. 만석 기준으로 자리가 남을 때만 현장 판매·입장을 한다.

## 2. 불편한 점
근무자가 **네이버 예약창 · POS · 주차 웹 · 열쇠 기록 웹**을 오가며 맞춰 보고 판단해야 한다.
- 이름으로 구매자 목록을 찾는 시간
- 키 번호를 메모장에 손으로 적는 일
- 반납이 늦은 키의 주인을 찾아 전화하는 일
- 예약 손님 자리를 남기고 현장에서 몇 장 팔 수 있는지 매번 판단하는 일
- 주차 웹에 차량번호를 따로 넣는 일

## 3. 새로 만드는 방향 (제로베이스)
- 아스타나 앱의 것은 **아무것도 가져오지 않는다.**
  - 별빛(충전 결제), 고객·관리자·근무자·대표자 앱 나눔, 요금·열쇠·예약 규칙 모두 처음부터 다시 정한다.
- 하나로 합칠 일
  1. 네이버 예약자 입장·퇴장 통제
  2. 현장 결제 (POS 연계)
  3. 열쇠 관리
  4. 주차 관리 웹 입력
- 근무자는 **POS PC 화면(1024×768) 한 장**에서만 일한다.

## 4. 쓰는 사람 (새로 정의)
| 누구 | 무엇으로 | 하는 일 |
|---|---|---|
| 근무자 | POS PC의 **입장 데스크** 한 화면 | 네이버 예약자 입장, 현장 결제, 열쇠 지급·반납, 주차 등록 |
| 손님 | **앱 없음.** 네이버로 예약하거나 현장에서 구매 | — (문자 안내도 보내지 않음) |
| 사장님 | 따로 앱을 만들지 않음. 데스크의 운영 설정에서 성수기 기간을 정함 | 성수기 기간 설정 |

이 시스템은 손님용 앱이 아니다. **근무자의 편리성**만 높인다.

## 5. 정한 규칙
| 규칙 | 내용 |
|---|---|
| 열쇠 | 45개 = **기본 40개 + 유동 5개** |
| 좌석 | 내부 4인석(입식·좌식) 39석 |
| 유동 열쇠 | 이론상 40석이 필요하지만 실제로 40석이 다 찬 적은 없음(카페 쪽으로 나가는 손님 등). 그래서 기본 40개를 넘으면 유동 5개를 **안에 빈 좌석을 보고** 쓴다 |
| 이용시간 — 성수기 | 평일·휴일 구분 없이 **17:30 입장까지 1시간 50분**, **18:00 입장부터 무제한** |
| 이용시간 — 비수기 | **평일은 항상 무제한**, 휴일(토·일·공휴일)은 성수기와 같음 |
| 성수기 기간 | 운영 설정에서 기간을 정함 (예: 여름방학·겨울방학) |
| 입장 | 손님 안내는 예약 시간 5분 전부터, 입장은 30분 단위. **근무자는 예약 당일이면 시간과 상관없이 입장 처리 가능** (내부가 비었거나 일찍 들여도 문제없을 때 — 예: 17:30 예약을 10:00에). 성수기 · 비수기 구분 없음. 일찍 들어와도 **이용시간(1시간 50분) · 반납 시각 · 초과요금은 예약 시간부터** 계산 → 일찍 온 만큼 더 놀 수 있음 ("오늘은 예약이 적어서 일찍 들어가 더 놀고 가세요"). 다른 날 예약은 입장 불가 |
| 열쇠판 색 | 빈 열쇠 회색 · 예약 입장시간부터 1시간 50분까지 검정(숫자·이름) · 2시간까지 분홍 · 2시간 넘으면 빨강 |
| 현장 결제 | 데스크에서 결제하지 않음. "결제하기"로 POS 창 전환 → 결제 → POS 최소화 → "결제 완료"로 열쇠 등록 |
| 주차 | 아마노코리아 할인등록 웹 화면을 데스크가 대신 조작(동기화). 할인유형 3시간 · 5시간 · 15시간 |
| 반납 지연 | 문자·전화 안내 없음(업무용 화면). 반납 시각이 지나면 열쇠 팝업에 초과 경과시간과 초과요금이 실시간으로 올라감 |
| 방문 사은권 | **10회 방문마다 2만원 사은권**(명함식 카드). 근무자 화면은 실제 회차(11번째), 영수증은 10회 단위로 다시 셈(11회차 → 1번째). 10·20·30번째에 사은권 증정 알림 |
| 초과요금 | 예약 입장시간부터 **1:50:00까지 페널티 없음**, **1:50:01부터 카운트업**. **2:00:00 정각 5,000원**, **2:10:00 정각 10,000원** … 10분이 꽉 찰 때마다 5,000원씩 오름. **열쇠 수만큼 곱함** (열쇠 2개면 2:00:00에 10,000원). 무제한 손님은 없음 |

### 아직 임시 값
| 규칙 | 체험판 임시 값 | 정할 것 |
|---|---|---|
| 열쇠 지급 단위 | 입장권 1장 = 열쇠 1개 | 네이버 입장권 1장이 한 팀(4인석 1개)인지 |
| 현장 입장권 가격 | 16,000원 | POS에 등록된 상품·가격을 그대로 씀 |
| 공휴일 | 체험판은 몇 날짜만 넣어 둠 | 공휴일 달력 자료로 자동 |

## 연속예약 (사용자 지시 10/6)
- 같은 사람(이름 + 전화번호)이 **2시간 이내 간격으로 이어서** 예약하면(예: 14:30 · 16:30) 퇴장 없이 이어서 쓰는 예약으로 본다
- 첫 예약 카드에 **★n타임 연속예약** — 근무자가 연속 이용자인 것을 알고 신발장을 관리
- 첫 예약에서 입장 처리하면 **묶음의 모든 예약을 이용완료** (네이버는 첫 예약을 바로, 나머지는 뒤에서 차례로 · 실패하면 2분마다 자동으로 다시)
- 열쇠 이용시간: 1타임 1시간 50분 · 2타임 3시간 50분 · 3타임 5시간 50분 … (n × 2시간 − 10분, 예약 시간부터). 무제한 시간이 끼면 무제한
- 뒤 예약 카드는 "연속예약 2/2 · 첫 예약 14:30" — 따로 입장 처리하지 않음
- 열쇠는 첫 예약 수량만큼, **열쇠마다** 이어지는 타임 수로 이용시간 (예: 12:00 3장 + 14:00 2장 → 2개 3시간 50분 · 1개 1시간 50분). 뒤 타임에 사람이 늘면 거기서 묶음이 끊기고 늘어난 예약은 따로 입장
- **2시간 이내 간격이면 연속이용**, 끝나는 시각은 **마지막 예약 시간 + 1시간 50분** (예: 12:00 · 13:30 → 15:20까지). **2시간보다 긴 간격**(예: 11:30 · 14:00)은 연속이용이 아님 — 빨간 "⚠ 연속이용 아님"으로 표시, 각각 1시간 50분, 나갔다가 다음 예약 시간에 다시 입장 안내. (중간 열쇠 부족 · 매진 뒤 뒷시간 예약으로 이어 쓰려는 것 방지 — 사용자 지시)
- 방문 횟수(마일리지 · 영수증)는 네이버와 같이 **예약 건수**로 셈: 한 번에 3장 = 1회, 1장씩 3번 = 3회, 연속예약 2타임 = 2회. 열쇠는 어느 경우든 장수만큼

## 현장입장 입장시간 (사용자 지시 10/6)
- 현장입장의 입장시간 = **접수한 시각 직전의 30분 칸** (예: 10:12 접수 → 10:00 입장). 늦게 들어가고 싶은 손님은 10:31 이후에 접수
- 이용시간 · 반납 시각 · 초과요금 · 입장권의 입장시간 모두 이 시각 기준. 18:00 칸부터 무제한

## 네이버 판매 수량 자동 조절 (사용자 지시 10/6)
- 목적: 2시간(4타임) 동안 안에 있는 손님이 **40~43팀**에 수렴. 비인기 타임은 덜, 인기 타임은 더 연다.
  - 내부는 4인석 39개, 열쇠 · 신발장 45개. 4타임 40장이 매진이어도 부모가 밖에 나와 3~5석이 비는 일이 많아 현장 판매를 해 왔음 → 이것을 데스크가 숫자로 계속 따라감
- **가동하는 날: 성수기(평일 · 휴일) · 비수기 주말 · 공휴일. 비수기 평일은 완전히 제외.** 18:00~ 무제한 타임도 제외
- ★ **가장 중요: 어느 2시간(연속 4타임)도 상한(기본 43)을 넘지 않는다.** 13장 × 4 = 52 같은 일이 없게 '최악의 경우'로 셈
  - 시작한 타임 = 실제 예약 + 실제 현장 · 안 시작한 타임 = **열어 둔 회차당 수량이 모두 팔린다고** + 현장 + 예상 현장
  - 바꿀 수 없는 먼 타임도 지금 열린 수량 그대로 셈. 그래도 넘는 묶음이 있으면 그 묶음의 안 팔린 수량을 줄임 (먼 타임 포함). 이미 팔린 것만으로 넘으면 더 줄일 수 없음
  - 여러 칸을 바꿀 때는 **줄이는 것부터** 넣음 (바꾸는 동안에도 넘지 않게)
- 10분마다(운영 설정 → 네이버 설정에서 켬): 네이버를 새로 읽고 → 계산 → 바뀌는 타임만 네이버 '회차당 수량'을 바꿈 (예약현황 칸의 하늘색 [예약가능] → 수량 → [설정변경])
- 계산 (`prototype/desk.html` 의 `planCaps`):
  - 바꾸는 타임 = 아직 시작 안 한 **지금 · 앞 3타임**. 예약 수에서 시작해 한 장씩 더 엶 — 그 타임이 든 모든 4타임 묶음의 최악 합이 **목표(기본 42) 안일 때만**
  - 한 장씩 줄 때 **예상 수요**가 큰 타임 먼저 ((예상 수요 + 1) ÷ (더 준 수 + 1)): 예상 수요 = 지금 예약 + **예약 속도**(최근 30분 늘어난 수) × 남은 시간, 과거 같은 날 종류(성수기/비수기 · 평일/휴일) **같은 타임의 실제 마감 수**(최근 8번)와 평균
  - **예상 현장** = 오늘 최근 3타임 현장 평균과 과거 같은 타임 현장 평균의 평균
  - 회차당 수량 = 그 타임 예약 + 더 연 수. 한 타임 최대 13 · 이미 예약된 수보다 적게는 안 함 (자리가 없으면 예약 수로 닫음)
  - 10분마다 다시 계산 → 안 팔린 비인기 타임 몫은 그 타임이 시작하기 전까지 인기 타임으로 옮겨 감
- 예약 속도 · 과거 실제 수는 POS PC 에 저장 (날마다 · 타임마다, 타임이 시작하면 실제 수 기록)

### POS PC 부담 (현장 통제가 멈추지 않게)
- 데스크 화면은 기다리지 않음: 네이버 일은 숨은 네이버 창이 차례대로(한 번에 하나) 하고, 데스크는 결과만 받음. 한 번에 2분이 넘으면 포기
- 10분마다 읽을 때 숫자가 바뀐 칸만 다시 엶 (카드를 기억). 바꿀 칸만 누름
- 입장 · 현장입장 창이 열려 있으면 그 10분은 다음 분으로 미룸. 네이버 불러오기 중이어도 미룸
- 3번 연속 실패하면 30분 쉼 (네이버 창을 붙잡고 있으면 이용완료 · 불러오기가 늦어지므로)
- 5분마다 네이버 · 아마노(뒤) 창의 메모리를 보고, 쉬는 중에 700MB 를 넘으면 그 창만 새로 고침 (로그인 유지). 데스크 화면은 건드리지 않음
- 기록은 최근 60줄만, 예약 속도 기록은 타임마다 40개만 남김

## 입장권 목록 · 기록 삭제 (사용자 지시 10/7)
- 맨 위 [오늘 입장권 총 판매수 = n장] 버튼 → 그날 입장권 목록: 이름(현장은 '현장구매자') · 입장시간 · 장수 · [기록 삭제]
- 기록 삭제 = 시험으로 잡힌 손님을 판매수 · 수량 자동조절 통계(예약 속도 · 과거 실제 수)에서 뺌
  - 네이버 이용완료 손님: 네이버 기록은 그대로 두고 이 PC에서만 뺌 (예약번호를 그날 저장 파일 x 에) · [되살리기] 가능
  - 현장구매자: 기록 자체를 지움 (열쇠를 갖고 있으면 빈 열쇠로) · 되돌릴 수 없음
- 지난날 목록은 보기만

## 이용완료 횟수 문구 · 같은 시간 나눠 한 예약 (사용자 지시 10/7)
- 횟수 = 네이버 '완료 n' (같은 네이버 아이디의 이용완료된 **예약 건수**, 장수와 무관). 우리는 네이버 숫자를 읽기만 하므로 '방문'이라고 하지 않음 (현장구매 · 다른 아이디 · 장수 때문에 다툼이 생김)
  - 카드: 완료 = "N번째 예약완료" · 입장 전 = "완료 8 · 취소 2 → 9번 완료 예정"
  - 입장권 기본 양식(ENTER_FORM ver 4): "네이버 예약 {누계}번 이용완료" · "{기준회}번마다 2만원 사은권을 드려요" · "[예약 1번 = 예약시 구매수량 무관/예약 수]"

## COM 포트 차례 · 출력 실패 문구 (현장 10/17 — 1.45 [2번 성공으로 시험 출력] '출력 실패: ����…COM1…')

  - **데스크 안의 출력 · 현금통은 포트마다 하나씩 차례로** (`apps/desk/src/com-queue.js`) — 겹치면 앞의 것이 끝난 뒤 바로
  - **다른 프로그램(OKPOS 출력 등)이 잠깐 쥐고 있으면 0.3초마다 다시 열어 봄**: 출력 10초까지 · 현금통 2초까지(도우미) — 그래도 안 비면 "포트를 다른 프로그램(OKPOS)이 쓰는 중 — COM1 이 10초 기다려도 비지 않음. 잠시 뒤 다시 해 보세요 (원래 오류)"
  - 쓰기 대기는 크기 · 속도로: 입장권(글만)은 예전처럼 8초쯤 · 쿠폰 그림은 보내는 시간의 두 배를 더함 (예전 1.45 는 늘 90초)
- [2번 성공으로 시험 출력]: 누르면 "시험 출력 보내는 중… (쿠폰 그림이라 n초쯤 걸려요)" · 보내는 중에 또 누르면 "앞 출력을 아직 보내는 중이에요"
- 시험(가짜 COM 포트 · PowerShell 7): 보통 출력 바이트 그대로 · 1.6초 막혔다 풀리면 기다렸다 출력 · 계속 막히면 위 한글 문구 · 현금통 도우미도 같음

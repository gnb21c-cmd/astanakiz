# 입장 데스크 화면과 연동 계획 (네이버 · POS · 주차)

목표: 근무자가 **POS PC 화면 한 장(1024×768)** 에서만 일한다.
네이버 예약창, POS, 주차 웹, 열쇠 기록 웹을 오가며 판단하던 일을 없앤다.

체험판: `prototype/desk.html` (예시 데이터, 실제 연동 없음. 규칙은 `docs/OPERATION.md` 5장)

## 화면 구성 (사장님 스케치 기준, 1024×768 한 장)
| 위치 | 내용 |
|---|---|
| 왼쪽 | 날짜 ← → · 시간(10:00~19:30)별 **확정 / 잔여** (네이버 값). 오늘은 "입장 전" 수량도 표시 |
| 가운데 | 맨 위 **새로고침** 버튼 — 네이버 예약은 09:50부터 매시 20분 · 50분에 자동으로 불러오고(버튼에 "10:20 불러옴 · 다음 10:50"), 그 사이에 들어온 예약(예: 09:58에 10:00 예약)은 근무자가 이 버튼으로 바로 불러옴 · 그 아래 고른 시간의 **예약자 명단** (스크롤). 카드마다 예약자 · 전화번호 · 이용일시 · 수량 · 결제상태(네이버 화면의 붉은 밑줄 항목) |
| 오른쪽 위 | **열쇠판** 10칸 × 5줄 (1~45번). 사용 수 · 현장 판매 가능(+유동) |
| 오른쪽 아래 | **주차등록** (아마노 화면 동기화): 입차일 · 차량번호 · 검색 · 조회 목록 · 주차시간 · 할인유형(3·5·15시간) · 할인내역 |

## 열쇠판 색
| 상태 | 표시 |
|---|---|
| 빈 열쇠 | 회색 숫자 · 회색 칸 |
| 입장 ~ 1시간 50분 | 검정 숫자 · 이름 · 검정 테두리 |
| 1시간 50분 ~ 2시간 | 분홍 칸 |
| 2시간 넘음 | 빨강 칸 |

- 시간은 **네이버 예약 입장시간**부터 셈 (현장입장자는 입장 시각부터).
- 무제한 손님(18:00 입장 이후, 비수기 평일)은 계속 검정.
- 열쇠를 누르면 그 손님의 열쇠 팝업: 이름 · 전화번호 · 입장 · 이용 시간 · 열쇠 수

## 반납과 초과요금 (열쇠 팝업)
1. 반납 시각이 지나면 팝업에 **초과 경과시간**이 초 단위로 올라가고, 그 밑에 **초과요금**이 택시 미터기처럼 올라감
   - 10분마다 5,000원 × 아직 가진 열쇠 수 (열쇠 2개면 10분에 10,000원)
   - 구간: ~1:50:00 없음 · 1:50:01 카운트 시작 · 2:00:00 정각 5,000원 · 2:10:00 정각 10,000원 … (10분이 꽉 찰 때 오름)
2. 금액이 생기면 **POS로 결제 · 금액** 버튼이 나옴. 누르는 순간 금액이 고정되고 POS 화면으로 전환
3. POS에서 그 금액을 결제하고 POS를 최소화 → 같은 팝업으로 돌아오며 "초과요금 결제 완료"로 바뀜
4. 반납: 열쇠가 여러 개면 **17번만 · 18번만 …**(5개씩 줄) 과 **모두 반납**, 하나면 **n번 반납 · 퇴장**
   - 초과요금이 있으면 결제한 뒤에 반납 버튼이 켜짐
- 팝업 크기는 열쇠 10개(5개 × 2줄)가 들어가도록 고정

## 흐름
### 네이버 예약자
1. 왼쪽에서 시간을 누름 → 가운데에 그 시간 예약자 명단
2. 카드에 "완료 7 → 이번 8번째 방문"이 보임. 예약자 **카드를 누름** (미입장 카드는 하늘색 · "미입장", 입장완료 카드는 회색 · "이용완료") → 네이버 예약자 팝업 (예약자 · 전화번호 · 이용일시 · 수량 · 결제상태)
3. 열쇠 1~45번이 **15칸 × 3줄**로 나옴. 이미 지급된 번호는 옅은 회색으로 눌리지 않음
4. 네이버에서 산 **예약 수량만큼** 지급할 번호를 누름 (수량을 따로 고르지 않음, 전화번호 입력·결제 없음)
5. **등록 완료** → 열쇠판에 이름이 뜨고 네이버 이용완료 처리 (이 화면에서 끝)
- 예약 5분 전부터 등록 가능. 이용완료된 카드를 누르면 지급한 열쇠 번호를 보여 줌

### 현장입장자
1. 열쇠판에서 **빈 열쇠**를 누름 → 팝업 (고객명 "현장입장자" 고정)
2. 전화번호는 POS PC에 USB로 연결된 키패드로 입력 (입력칸에 커서가 미리 가 있음). 수량을 늘리면 다음 빈 열쇠가 이어서 붙음
3. **결제하기** → 아침부터 켜져 있는 POS 프로그램 창을 앞으로 띄움 (이 화면에서 결제하지 않음)
4. POS에서 결제를 끝내고 POS 창을 최소화 → 열려 있던 팝업으로 자연스럽게 돌아옴
5. **결제 완료** → 입력한 정보를 열쇠판에 등록
- 예약 손님 자리를 먼저 남기고 판매 가능 수를 계산. 기본 40개를 넘으면 "빈 좌석 확인했어요"를 눌러야 유동 열쇠로 등록됨

### 주차등록 (아마노코리아) — 화면 동기화, 자세히: `docs/AMANO.md`
1. 입차일(기본 전날) · 차량번호 → 검색 → 아마노 화면에도 같은 값 입력 · 검색 버튼 누름 → 조회 목록을 읽어 옴
2. 차량 선택 → 주차시간 표시 → 할인 버튼(3시간 · 5시간 · 15시간) → 아마노 화면의 같은 버튼을 누르고 할인내역을 읽어 옴

## 현장 판매 가능 판단 (예약자 우선)
지금부터 이용시간 동안 5분마다
`기본 열쇠 40 − (안에 있는 손님 열쇠 + 그때 와 있을 네이버 예약 열쇠)` 를 계산해 가장 작은 값만큼 판다.
예약 손님 자리를 먼저 남기므로 근무자가 따로 판단하지 않는다.
- 무제한 손님은 반납할 때까지 열쇠를 계속 쓰는 것으로 본다.
- 기본 40개를 넘으면 **유동 열쇠 5개**까지 팔 수 있다. 이때는 화면이 "안에 빈 좌석을 보고 판매"를 안내하고, 근무자가 "빈 좌석 확인했어요"를 눌러야 결제 버튼이 켜진다.

## 반납 지연
- 문자·전화 안내는 하지 않는다 (업무용 화면). 늦은 열쇠는 초과요금으로 처리한다.
- 늦은 열쇠는 열쇠판에서 분홍·빨강으로 바뀌고, 누르면 이름·전화번호가 바로 보임 → 일일이 찾을 필요 없음

## 연동 방법

데스크 앱은 **POS PC에 설치하는 Windows 프로그램**으로 만든다.
그래야 이 PC에 로그인된 네이버 예약관리·주차 웹을 앱이 대신 조작하고, POS 자료를 읽을 수 있다.

### 네이버에서 읽어 와야 하는 값
| 값 | 어디에 쓰나 |
|---|---|
| 예약자 · 전화번호 · 예약번호 · 상품 · 이용일시 · 수량 · 결제상태 | 예약자 카드·팝업 |
| 상태 (확정 / 완료 / 취소) | 미입장 · 이용완료 표시 |
| **이름 밑 "완료 n · 취소 n"** | 방문 회차. **미입장(확정) 때 읽은 완료 n**이 이번 방문 전까지 횟수 → 등록 완료 때 **n+1번째 방문**으로 정함 |

- 주의: 이용완료를 누르면 네이버의 완료 수가 1 늘어나므로, **미입장일 때 읽은 값**을 저장해 두고 쓴다 (두 번 더하지 않게).
- 시간대 목록의 확정 / 잔여 수량

### 방문 회차와 사은권 (10회마다 2만원 사은권)
| 회차 | 근무자 화면(카드·팝업) | 입장표 영수증 |
|---|---|---|
| 1~9회차 | 실제 회차 (예: 9번째 방문) | 같은 숫자 |
| 10회차 | 10번째 방문 + **2만원 사은권 증정** 표시, 등록 알림 "사은권을 드리세요" | ★ 10번째 방문 ★ · **2만원 사은권 증정!** |
| 11회차 | 11번째 방문 (실제 회차 그대로) | ★ **1번째** 방문 ★ (10회 단위로 다시 셈) |
| 20회차 | 20번째 방문 + 사은권 증정 | ★ 10번째 방문 ★ · 사은권 증정 |

- 사은권은 영수증이 아니라 이미 준비된 **명함식 카드**를 근무자가 따로 드린다. 영수증·화면은 그때를 알려 주기만 한다.
- 지금은 근무자가 확인하고 영수증에 색연필로 쓰던 일을 대신한다.

### 1. 네이버 예약 → 예약자 정보 자동 채우기
**정한 방식: 예약관리 화면 자동 읽기(A).** 코드와 시험이 들어가 있음 — 자세히: `docs/NAVER.md`

| 방법 | 내용 | 장단점 |
|---|---|---|
| **A. 예약관리 화면 자동 읽기 (추천)** | 데스크 앱 안에 네이버 예약관리(파트너센터)를 로그인해 두고, 오늘 예약 목록을 몇 분마다 읽어 옴. 입장 처리 때 이용완료도 앱이 대신 누름 | 승인 절차 없이 가능. 네이버 화면이 바뀌면 고쳐야 함. 이용 약관 확인 필요 |
| B. 예약 알림 메일 읽기 | 네이버가 보내는 예약·취소 알림 메일을 읽어 옴 | 이용완료는 자동으로 못 누름. 메일에 전화번호가 다 나오는지 확인 필요 |
| C. 엑셀 올리기 (비상용) | 예약관리에서 예약자 목록 엑셀을 내려받아 올림 | 하루 몇 번 손이 감 |
| D. 네이버 공식 예약 API | 네이버 제휴 업체만 쓸 수 있음 | 소규모 매장은 어려움 |

### 2. POS 연계 → 현장 결제
**정한 방식: 화면 전환.** "결제하기"를 누르면 데스크 앱이 이미 켜져 있는 POS 프로그램 창을 맨 앞으로 띄운다(Windows 창 전환).
POS에서 결제 후 POS 창을 최소화하면 데스크 팝업이 그대로 보인다. "결제 완료"를 눌러 열쇠판에 등록한다.
POS 창을 찾으려면 POS 프로그램 이름(창 제목)이 필요하다.

아래는 나중에 더 줄일 때의 선택지다.

| 방법 | 내용 | 장단점 |
|---|---|---|
| **A. POS 결제 읽어 오기 (먼저)** | 지금처럼 POS에서 결제하면, 데스크 앱이 POS 자료를 읽기만 해서 "입장권 1장 결제됨 → 열쇠 배정"으로 바로 띄움 | 계약·승인 없이 가능. POS 화면을 한 번은 눌러야 함 |
| B. POS에 주문 보내기 | 데스크 앱에서 장수를 고르면 POS로 주문이 넘어가 결제만 하면 됨 | POS 회사의 외부 연동 허용 필요 (POS 회사·대리점 문의) |
| C. 카드 단말기 직접 연결 | 데스크 앱이 단말기(VAN)로 바로 결제 요청 | VAN 대리점 계약 필요. POS 매출과 따로 관리됨 |

### 3. 주차등록 (아마노코리아)
**정한 방식: 화면 동기화.** API를 쓰지 않고, 앱이 맨 뒤에 열어 둔 아마노 웹 화면(모니터 한 대에 겹쳐 둠)을 데스크 앱이 대신 입력·클릭하고 결과를 읽어 온다. 코드와 시험이 들어가 있음.
버튼은 화면 좌표가 아니라 웹페이지 안의 칸·버튼 이름으로 찾는다(창이 움직여도 정확). 자세히: `docs/AMANO.md`

## 영수증 프린터 (80mm 감열지)
운영 설정 → **프린터** 탭
- **프린터 찾기**: POS PC에 연결된 프린터 목록을 읽어 와 하나를 고름 → **테스트 출력**
- **출력 양식**: 입장표 · 초과요금 영수증. 양식마다 글을 고칠 수 있고, 오른쪽에 80mm 폭 미리보기가 바로 바뀜
  - 넣을 수 있는 값: {매장} {날짜} {시각} {고객} {전화뒤4} {열쇠} {수량} {입장} {반납} {방문회차}(10회 단위) {사은권} {초과시간} {금액}
  - 값이 비어 있는 칸이 든 줄은 출력하지 않음 (예: 현장입장자는 방문회차가 없어 '★ n번째 방문' 줄이 빠지고, 10번째가 아니면 사은권 줄이 빠짐)
  - 줄 앞에 `#` 크게 가운데 · `^` 가운데 · `---` 구분선
- **자동 출력**: 입장표는 "등록 완료"(네이버 예약자 · 현장입장자) 때, 초과요금 영수증은 "초과요금 결제" 뒤 POS에서 돌아올 때
- 실제 앱: Windows 프로그램이 PC의 프린터 목록을 읽고, 고른 프린터로 창 없이 바로 출력한다 (용지 폭 80mm, 인쇄 폭 약 72mm). 프린터가 안 잡히면 화면에 알린다.
- 무엇을 출력할지(양식 종류)는 더 정해지면 늘린다.

## 받아야 할 자료
1. **네이버**: 예약관리의 오늘 예약자 목록 화면 사진(개인정보는 가려도 됨), 이용완료 버튼 위치, 예약 알림 메일 한 통(가려서)
2. **POS**: 키즈 PC의 POS 프로그램 이름(창 제목), 키즈 입장 상품 목록(이름·가격)
3. **주차**: 화면 사진 받음, 할인유형 3·5·15시간으로 정함
4. **열쇠**: 지금 열쇠를 등록하는 웹이 무엇인지, 이 앱으로 대체해도 되는지
5. **규칙**: `docs/OPERATION.md` 5장의 표

# 네이버 예약 연동

API는 쓰지 않는다. 앱이 맨 뒤에 **네이버 예약관리(스마트플레이스 파트너센터) 예약현황** 창을 열어 두고, 화면을 읽고 버튼을 대신 누른다.

## 창 배치 (모니터 한 대)
```
맨 앞   입장 데스크
가운데  POS (OKPOS Program)
맨 뒤   아마노 할인등록 · 네이버 예약관리 (입장 데스크 앱이 열어 둔 창)
```

## 처음 한 번 (POS PC)
1. 운영 설정 → 아마노 · POS → **네이버 화면 보기 (로그인)** → 네이버 로그인 (2단계 인증이 있으면 그대로). **'로그인 상태 유지'를 꼭 체크** — 안 하면 로그인이 창을 닫을 때까지만이라 앱을 껐다 켜면 풀린다
2. 예약관리 → **예약현황** 화면까지 들어감 → **지금 화면을 시작 화면으로**
3. 그 뒤로는 로그인 상태가 이 PC 앱에 계속 남는다 (네이버 비밀번호는 앱에 저장하지 않음)

## 실제 네이버 화면 (2026-10-05 저장본으로 확인)
| 화면 | 주소 | 읽는 것 |
|---|---|---|
| **예약 목록** | `/bizes/{업체번호}/booking-list-view` | 날짜 "이전 26. 10. 5.월 다음", 줄마다 상태 · 예약자 · 전화번호 · 예약번호 · 이용일시 · 상품 · 수량(4인 입장권 n) · 결제상태. 위에 "124건" |
| **예약현황** | `/bizes/{업체번호}/booking-calendar-view` | 머리 = 상품 이름(맨 앞 '회차' 칸 제외), 줄 = 시간, 칸 = "오전"+"10:00" + 버튼(title 예약가능 · 잔여예약 · 확정 · 이용완료, 숫자) |
| 예약정보 (예약현황에서 칸의 버튼) | `.../booking-calendar-view/bookings?bizItemId=…&date=…&status=…` | 탭 "완료 9", 카드: 이름 밑 **"완료 11, 취소 2"**, 예약자 · 전화번호 · 예약번호 · 상품 · 이용일시 · 수량 · 결제상태 |

- 예약 목록은 **50줄씩, 아래로 내리면 더 불러옴**("로딩중") → 데스크가 끝까지 내려 "124건"을 다 읽는다. 같은 줄의 빈 복사본은 뺀다
- 이용완료 손님 카드의 "완료 n"에는 **이번 방문이 들어 있음** (예: 오늘 10시 이용완료 송나라 → 완료 11 = 11번째 방문). 미입장(확정) 손님은 완료 n + 1 이 이번 방문
- **실제 수집(보고 시스템 `report` 저장소의 네이버 아침 수집, 10/4)에서 확인된 것 — 데스크에도 반영:**
  - 칸 폭이 좁으면 시각에 **오전 · 오후가 빠짐** → 영업시간으로 읽음 (1:00 = 13:00, 10 · 11 · 12시는 그대로)
  - 오른쪽 예약정보 목록은 **스크롤되는 칸이고 내려야 카드가 더 나옴** → 끝까지 내려 읽고, 이용완료할 카드도 내려 가며 찾음
  - 칸을 누르면 주소가 `…/bookings` 로 바뀌고 **표가 새로 그려짐** → 다른 칸을 누르기 전에 열린 목록을 [닫기]로 닫음
  - 칸 폭에 따라 글이 '이용완료'/'완료', '잔여예약'/'잔여' 로 바뀜 — 데스크는 글이 아니라 버튼의 title 로 찾음 (POS PC에서 title 도 바뀌는지 확인)
  - 같은 POS PC에서 보고 시스템 수집(아침 09:15, 별도 브라우저)도 네이버에 로그인해 있음 — 로그인이 따로라 서로 부딪히지 않음. **로그인 창이 두 곳**이라는 점만 직원에게 안내
- 클래스 이름 뒤 해시(`__VGAjs` 등)는 네이버가 바꿀 수 있어 앞부분으로 찾는다
- 저장본에서 확인함: 목록 50명(총 124건) · 예약현황 칸(평일 입장권 10:00 잔여 1 · 이용완료 9, 야간자유 18:00 잔여 6 · 이용완료 4) · 카드 8장의 완료 n

## 데스크가 읽는 순서
**예약현황(일간)만 쓴다.** 예약자관리(목록)는 쓰지 않는다 — 현장 시험(10/6)에서 목록이 '한달'(26.10.5 ~ 11.4)로 되어 있어 [다음]·[이전]이 한 달씩 움직여 날짜를 못 맞추고 왔다갔다 했음.
1. 예약현황 → 그 날짜 → 시간 칸별 확정 · 이용완료 · 잔여 (데스크 왼쪽 **시간 · 확정 · 잔여**)
2. 입장권 칸마다 [확정] · [이용완료] 를 열어 카드를 끝까지 내려 읽음: 예약자 · 전화번호 · 예약번호 · 수량 · 결제상태 · 완료 n · 취소 n
3. 칸 숫자가 그대로면 기억한 카드를 씀 → 처음 한 번만 오래 걸리고, 다음부터는 바뀐 칸만 다시 엶
- 날짜 칸이 기간(“~”)이면 바로 멈추고 "'일간'으로 바꿔 주세요". 날짜가 넘었다 돌아왔다 하면 두 번째에 멈춤

## 데스크가 하는 일
| 언제 | 네이버 화면에서 (자동) | 데스크에 |
|---|---|---|
| 앱 켤 때 · 날짜 ← → · **자동: 09:50부터 매시 20분 · 50분(19:20까지, 오늘)** · **[새로고침]: 그 사이 새 예약을 근무자가 바로** | 위 '읽는 순서' 1~3 | 시간별 확정 · 잔여, 예약자 명단(예약자 · 전화번호 · 이용일시 · 수량 · 결제상태 · 완료 n · 취소 n) |
| 네이버 예약자 **등록 완료** | 그 예약 칸 → 카드의 **이용완료** → 확인 → 완료로 바뀐 것을 다시 읽어 확인 | 확인되면 열쇠 등록, 방문 회차 = 미입장 때 읽은 완료 n + 1 |
| 네이버가 안 될 때 | — | "네이버 이용완료 실패" + **네이버 없이 열쇠만 등록** (나중에 네이버에서 직접 이용완료) |

- 상품은 이름에 **입장권**이 들어간 것만 (단체 · 열쇠분실 상품은 뺌)
- 오늘의 열쇠·입장 기록은 이 PC에 저장 → 앱을 껐다 켜도 열쇠판 유지

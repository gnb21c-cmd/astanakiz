# 최종 설치본 만들기 전 할 일

설치본(Windows 설치 파일)을 만들기 **직전**에 아래를 차례로 한다.

1. 현장 자료로 맞추기
   - 실제 아마노 할인등록 화면 저장 파일로 칸·표 이름 확인 (`docs/AMANO.md`)
   - ~~POS 프로그램 창 제목 확인~~ (OKPOS Program, 기본값으로 넣음)
   - 네이버 예약현황 실제 화면 저장 파일로 `naver-driver.js` 맞추기 (`docs/NAVER.md`)
2. 시험: `cd apps/desk && npm test` 모두 통과
3. **직원용 메뉴얼 PDF 만들기** (사용자 지시)
   - 그 시점의 실제 화면으로 캡처해 만든다 (화면이 바뀌면 메뉴얼도 다시)
   - 담을 내용: 아침 준비(앱 켜기 · 아마노 자동 로그인 확인) · 네이버 예약자 입장 · 현장입장(POS 결제 전환) · 열쇠 반납과 초과요금 · 주차등록 · 방문 회차와 사은권 · 프린터 · 문제가 생겼을 때
   - 직원들에게 배포
4. 설치본 만들기: `cd apps/desk && npm run dist:win`
5. POS PC에 설치 → 운영 설정(아마노 주소 · 아이디 · 비밀번호 · POS 창 제목 · 프린터) → 차량 한 대로 실제 시험

## 새 판 바꾸기 — "업뎃해" 하실 때만 · 고친 내용만 (사장님 11/18 — ver.2.30 부터)
- **원칙 (사장님)**: 고친 것은 모아 두었다가(feature/next) 사장님이 **"업뎃해"(업데이트 해 · 만들어)** 하실 때만 새 판을 냄 → 그때만 POS · 사무실 앱이 바뀜. 그 밖에는 아무것도 안 바뀜
- "업뎃해" → main 에 올림 → GitHub 가 설치 파일과 함께 **desk-patch.json**(작은 안내: 판 · 커밋 · 껍데기 · 묶음 sha512) · **desk-patch-files.json**(고친 파일 묶음: 동작 파일 `src` 전부 · 화면 `desk.html` · 설명서 사진, 약 2MB)을 Releases `v2.X`('최신' 표시)에 올림 (약 10분)
- 앱은 **켜고 1분 뒤 · 그 뒤 10분마다 desk-patch.json 만 봄** (보기만 — 이것으로는 아무것도 안 바뀜) → 새 판이면 묶음을 받아 sha512 를 맞춰 보고 앱 폴더 `patch\<판>` 에 풀어 둠
- 다 받으면 데스크 위 띠 **"새 판 ver.X 받음 · N초 뒤 바꿔요 (데스크만 몇 초 다시 켜짐) [지금 바꾸기] [30분 뒤에]"** → 1분 뒤 **데스크만 다시 켬** (설치 프로그램 · 프로그램 폴더 · 바탕화면 아이콘은 안 건드림)
  - 톡톡 보내기 · 재고 자동 오픈 중이면 끝날 때까지 미룸(2분마다 다시 봄) · [30분 뒤에] = 30분 뒤 다시 1분 띠 · 근무자가 프로그램을 끄면 다음에 켤 때 새 판
  - 운영 설정 → 기타 → **업데이트** 줄: 지금 판 · 마지막 확인 · 받는 중 % · 확인 못 한 까닭 · 앞 판으로 돌아간 까닭 · [지금 확인] · [지금 바꾸기]
  - 기록: 앱 폴더 `update-log.txt` (300줄) — 언제 받고 · 언제 바꿨는지 · 아이콘을 다시 만들었는지
- **문제가 나면 앞 판으로 저절로**: 켤 때 `boot.js`(껍데기 — 고친 내용으로 안 바뀜)가 판을 고름 · 고른 판이 켜지다 바로 멈추면 그 판을 빼고 다시 켬 · 3번 연속 화면까지 못 켜져도 앞 판(없으면 설치한 판) · 뺀 판은 다시 받지 않음(고친 다음 판을 기다림)
- **껍데기**(Electron 큰 판 · boot.js · 꾸러미)가 바뀐 판은 이 방식으로 못 바꿈 → 띠/설정 줄에 알림만 (저절로 설치하지 않음 — 그런 판을 낼 때는 미리 사장님께 말씀드림)
- **바탕화면 아이콘 지키기**: 앱이 켤 때마다 바탕화면 '아스타나키즈 입장 데스크' 아이콘이 없으면 다시 만듦 · 설치 파일도 끝날 때 아이콘이 없으면 만듦(`apps/desk/build/installer.nsh` — electron-builder 는 업데이트 · 덮어 설치 때 아이콘을 새로 만들지 않음)
- **현장 POS 는 컴퓨터를 켜면 데스크도 저절로 켜짐** (Windows 로그인 때 · 사무실 PC 는 안 켬) — 직원이 아이콘을 찾지 않아도 됨
- 왜 바꿨나 (11/17 저녁 · 11/18 아침): 예전(ver.2.27 ~ 2.29)은 새 판이면 설치 파일 전체(약 100MB)를 받아 **옛 프로그램을 지우고 다시 설치**했음 → 그 수십 초 동안 프로그램 파일이 없어, 꺼진 데스크를 다시 켜려고 아이콘을 누르거나 그때 POS 를 끄면 Windows 가 '바로 가기 문제 — 삭제하시겠습니까?'를 띄워 아이콘이 없어질 수 있음 · 한 번 없어진 아이콘은 업데이트로 다시 생기지 않음 · 데스크는 컴퓨터를 켤 때 저절로 안 켜졌음 → 11/18 아침 직원이 데스크를 못 켜 보고 시스템 · 제빵관리에 그날 자료가 없었음
- **넘어가는 판 (ver.2.30)**: 지금 POS · 사무실의 2.29 는 옛 방식이라 **2.30 만 마지막으로 옛 방식(설치 파일)으로** 들어감 → "업뎃해"는 데스크가 켜져 있고 손님이 없을 때(마감 직후 · 개점 전) · 2.30 설치 파일은 아이콘이 없으면 만들어 아이콘도 돌아옴. 2.31 부터 고친 내용만
- latest.yml 도 계속 올림 (꺼져 있던 PC 가 2.29 로 남아 있어도 다음에 켜면 한 번 설치해 새 방식이 됨)
- 처리 `apps/desk/src/patch.js`(받기 · 풀기 · 판 고르기 · 앞 판으로 — 시험 `test/patch.test.js`) · `updater.js`(1분 띠 · 기다림 — 시험 `test/updater.test.js`) · `boot.js`(시작 파일 · `package.json` main) · 연결 `main.js` `updStart` · `ensureDesktopIcon` · `autoStart` · 묶음 만들기 `apps/desk/scripts/make-patch.js`(`shell` → `src/shell.json` · `bundle`) · `.github/workflows/build-win.yml` 이 안내의 판이 다르거나 묶음이 없으면 멈춤
- 확인(11/18): 시험 · 실제 앱(Electron)으로 받기 → 1분 띠 → 다시 켬 → 받은 화면 · 깨진 판 → 앞 판 · 뺀 판 다시 안 받음 · **리눅스 포장(asar)** 으로 boot 가 앱 폴더의 판을 켜고 `app.relaunch` 로 스스로 다시 켜짐 · `installer.nsh` 는 electron-builder 와 같은 NSIS 3.0.4.1 로 번역됨 · 실제 Windows(아이콘 · 저절로 켜기)는 2.30 설치 때 처음

## 시험판 버전 (현장 시험 때)
- main 에 데스크 코드가 올라가면 GitHub 가 설치 파일을 만들어 Releases **시험판(최신)** 에 올린다 (`.github/workflows/build-win.yml`)
- 버전은 **ver.0.X**, 설치 파일을 만들 때마다 X 가 1씩 늘어난다 (첫 번호 ver.0.1). 화면 맨 위 "네이버 · 아마노 · POS 연결 ver.0.X" 로 새 설치본인지 확인 (사용자 지시)
- 현장 시험이 끝나면 정식 **Ver. 1.0**

# 두 PC 연결 — 현장 POS ↔ 사무실 PC (2026-11-06)

관리자는 사장님 한 사람이다. 수량 조절 · 운영 설정 · 근무자에게 남기는 메시지는 근무자에게 시킬 수 없으니 **사무실에서 같은 버전의 통합데스크로** 하고, 그 결과가 현장 POS 에 그대로 적용되게 한다. 반대로 현장 POS 의 지금 화면(예약 · 열쇠 · 판매 수량)이 사무실 PC 에 그대로 보인다 (사장님 11/06).

## 어떻게 이어지나 — 고정 IP 없이 '우편함'
- 현장 POS · 사무실 PC 둘 다 고정 IP 가 없어 서로 직접 이어지지 않는다. 그래서 **두 PC 모두 바깥 우편함에 자기 문서 하나를 덮어쓰고 반대편 문서를 읽는다** (둘 다 밖으로 나가는 연결만 씀).
- 우편함 = **보고 시스템 클라우드**(설문 보고함 · 키즈 실시간과 같은 곳 · 같은 **보고 열쇠**): `boards/{보고 열쇠}/deskSync/pos`(현장 POS 가 씀) · `deskSync/office`(사무실 PC 가 씀).
- GitHub 를 우편함으로 쓰지 않은 까닭 (사장님 제안 11/06 을 검토): ① 바뀔 때마다 기록이 영구히 쌓임 — 예약 손님 이름 · 네이버 상품 번호를 저장소에 넣지 않는 원칙과 맞지 않음 ② 현장 POS 에 쓰기 권한 토큰을 따로 넣어야 함 ③ 반영이 수십 초 ~ 분 늦을 수 있음. 보고 클라우드는 이미 연결돼 있고 문서 하나를 덮어써 기록이 쌓이지 않는다.
- **잠금**: 문서 안 내용은 **연결 코드**(현장 POS 가 만드는 16자리 · 예 `ABCD-EFGH-JKLM-NPQR`)로 잠근다 — 연결 코드 + 보고 열쇠 → scrypt → AES-256-GCM (압축 뒤). 보고 열쇠를 아는 사람도 내용을 읽거나 가짜 명령을 넣지 못한다 (지우거나 덮어쓰면 연결만 끊김). 문서마다 '누가 · 어느 버전'을 함께 잠가 다른 자리로 옮겨 붙여도 안 풀린다.
- **같은 버전끼리만**: 두 PC 의 버전(ver.n)이 다르면 아무것도 반영하지 않고 양쪽 화면에 "버전이 달라요 — 현장 POS ver.x · 이 PC ver.y".
- 앱 본체 `apps/desk/src/desk-sync.js`(Electron 없이 시험) · 연결 `main.js` '두 PC 연결' · 화면 `prototype/desk.html` `syncSnap` · `syncApply` · `syncRun` · `officeGate`.

## 주고받는 것
| 무엇 | 방향 | 규칙 |
|---|---|---|
| 운영 설정 (아래 '함께') | 양쪽 | 키마다 **늦게 바꾼 쪽**이 이김 · 처음 이을 때는 현장 POS 설정을 사무실 PC 가 받음 · 바꾼 때가 같은데 값이 다르면 현장 쪽 |
| 근무자 메모장 (근무자 · 내 메모 · 전달 · 접수 · 완료) | 양쪽 | 메모 · 전달마다 늦게 바꾼 쪽 · 지운 것은 양쪽에서 지움 · 근무자 목록은 늦게 바꾼 쪽 |
| 지금 화면 (오늘 예약 · 입장 · 열쇠 · 현장 · 서비스 키 · 판매 수량 칸 · 수량 조절 기록 · 재고 오픈 결과 · 재방문 이벤트 표시) | 현장 → 사무실 | **사무실 PC 가 켜져 있을 때만** 2초마다 바뀐 것 · 사무실이 꺼지면(2분 30초 소식 없음) 안 올림 |
| 명령 (수량 지금 조절 · 한 칸 판매 수량 · 재고 확인만 · 재고 지금 열기 · 네이버 새로고침) | 사무실 → 현장 | 현장 POS 가 네이버에 넣고 결과를 돌려줌 · 같은 명령은 한 번만 · 10분 넘게 늦게 닿은 명령은 안 함 |

- **함께 쓰는 설정**: 성수기 기간 · 판매 수량 자동조절(맨 위 [오늘 수량조절] 포함) · 입금대기 자동 취소 · 재고 자동 오픈 · 입장권 양식 · 프린트물 설정 · BC 양식 · 재방문 이벤트 · 현장 이벤트 · 설문 · 폰 실시간 현황 켜짐 (`desk-sync.js SHARED`)
- **각 PC 에만**: 프린터(포트 · 속도 · 현금통) · API(아마노 · 네이버 · 톡톡 로그인 · 주소) · 보고 열쇠 · 쿠폰 봉인 열쇠 · 방문 기록 비밀값 · **고객 세부 관리(손님 메모 · BC · 마일리지 SKIP)** — 손님 정보라 클라우드로 보내지 않음 → 사무실 PC 카드에는 손님 메모 · BC 표시가 없음
- 화면에 실리는 손님 정보는 오늘 예약자 이름 · 전화번호 등 현장 화면 그대로이고 **연결 코드로 잠긴 채** 우편함에 있다 (키즈 실시간 `deskLive/now` 는 잠그지 않은 열쇠 손님 이름 · 전화). 문서 하나를 덮어써 지난 기록은 쌓이지 않음.

## 사무실 PC 에서 되는 것 · 안 되는 것
- **됨**: 현장 화면 보기(시간 칸 · 카드 · 열쇠 창 · 입장권 목록) · 운영 설정 전부(각 PC 것 빼고) · 메모장(전달 남기기 · 메모) · 맨 위 [오늘 수량조절]
- **현장 POS 에 명령**: [새로고침] → 현장 네이버 새로고침 · 네이버 설정 [지금 조절] · [한 칸 시험] · 재고 [확인만] · [지금 한 번] — 결과는 화면 아래 알림 "현장 POS: … 됨 — 10:30 10→11"
- **막힘 (현장 POS 에서만)**: 입장 · 반납 · 결제 · 초과요금 · 서비스 키 · 이벤트 입장 · 열쇠 옮기기 · 출력 · 주차 · 고객 BC · 다른 날짜 보기 · 보고 보내기 → "사무실 PC — 이 일은 현장 POS 에서 해요"
- 사무실 PC 는 아마노 · 네이버 · 톡톡 · POS · 현금통 창을 **열지 않고**, 네이버를 직접 읽거나 바꾸지 않는다 (네이버 로그인도 필요 없음) · 보고(설문 · 실시간 · 재방문 · 이벤트)도 보내지 않음 · 오늘 기록 파일도 안 씀
- 맨 위 작은 표시: 사무실 PC = "사무실 PC · 현장 14:05 기준" (3분 넘게 소식이 없으면 "현장 소식 n분째 없음" · 버전 다름 · 연결 코드 확인) / 현장 POS = 사무실이 보고 있으면 "사무실 PC 연결됨" · 오류면 "두 PC 연결 확인"

## 처음 잇는 법 (사장님 한 번)
1. **보고 시스템 규칙에 `deskSync` 더하기** — 아래 '보고 시스템이 할 일' → Firebase 콘솔 → Firestore Database → 규칙에 붙여 넣고 [게시] (키즈 실시간 때와 같음). 게시 전에는 상태에 "열쇠나 모양이 틀림 (403) — 보고 시스템 규칙에 deskSync 가 있는지"
2. **현장 POS**: 운영 설정(시계 두 번) → **두 PC 연결** → 이 PC 역할 **[현장 POS (본 PC)]** → [지금 다시 켜기] → 연결 코드 16자리가 보임 (보고 열쇠는 기타 → 보고 앱에 이미 있음)
3. **사무실 PC**: 같은 버전 설치 파일로 설치 → 운영 설정 → 기타 → 보고 앱 **보고 열쇠**(현장과 같은 것) → 두 PC 연결 → **[사무실 PC]** → 연결 코드 넣고 [저장] → [지금 다시 켜기]
4. 15초 안에 사무실 PC 맨 위 "사무실 PC · 현장 hh:mm 기준", 현장 POS 맨 위 "사무실 PC 연결됨"
- 새 버전을 낼 때는 **두 PC 모두** 같은 설치 파일로 (한쪽만 바꾸면 "버전이 달라요" — 그동안 사무실 PC 는 반영 없음, 현장 POS 는 평소대로 동작)
- 연결 코드를 새로 만들면(현장 [새 코드 만들기]) 사무실 PC 에도 다시 넣는다 · 역할을 [안 씀]으로 하면 그 PC 는 예전처럼 혼자

## 우편함 쓰기 · 읽기 수 (Firestore 무료 한도: 하루 쓰기 2만 · 읽기 5만)
- 현장 POS: 사무실이 꺼져 있으면 15초마다 읽기 1(하루 영업 12시간 ≈ 2,900) · 쓰기는 설정 · 메모장이 바뀔 때만
- 사무실 PC 가 켜져 있는 동안: 양쪽 4초마다 읽기(시간당 900 × 2) · 현장 쓰기 = 화면이 바뀔 때 3초 간격 + 1분마다 · 사무실 쓰기 = 1분마다 + 바꿀 때
- 예) 사무실 PC 를 하루 8시간 켜 두면 읽기 약 1만 7천 · 쓰기 수천 — 키즈 실시간(1분마다 쓰기)과 합쳐도 무료 한도 안

## 보고 시스템이 할 일 (gnb21c-cmd/report — 규칙 한 덩어리)
`firebase/firestore.rules` 의 `match /boards/{board} { … }` 안, `deskStats` 아래에 더함:
```
      // 두 PC 연결 (통합데스크 현장 POS ↔ 사무실 PC · 2026-11-06) — astanakiz docs/SYNC.md
      //   문서 둘(pos · office)만 계속 덮어씀 · json = 잠긴 글(astanakiz-sync · 연결 코드 없이는 못 읽음) · 보고 앱은 읽지 않음
      match /deskSync/{doc} {
        allow read: if true;
        allow create, update: if (doc == "pos" || doc == "office")
          && exists(/databases/$(database)/documents/boards/$(board)/settings/main)
          && request.resource.data.keys().hasOnly(["json", "at"])
          && request.resource.data.json is string && request.resource.data.json.size() < 900000
          && request.resource.data.json.matches("(?s)^[{].*astanakiz-sync.*$")
          && request.resource.data.at is string && request.resource.data.at.size() < 40;
        allow delete: if isSender(board);
      }
```
- 확인할 것 (에뮬레이터): `pos` · `office` 만들기 · 고치기 · 읽기는 됨 / 다른 이름 · 설정 없는 열쇠 · 다른 칸 · `astanakiz-sync` 아닌 글 · 큰 글 · 로그인 없는 지우기는 막힘
- 읽기(통합데스크가 함): `GET …/documents/boards/{열쇠}/deskSync/{pos|office}` → `fields.json.stringValue` (없으면 404 = 아직 안 씀)
- 보고 앱 화면은 바꿀 것 없음

## 문서 모양 (`deskSync/{pos|office}` 의 `json`)
```jsonc
{ "type": "astanakiz-sync", "v": 1, "role": "pos", "build": "2.20", "n": 128, "at": "2026-11-06 14:05:12",
  "box": "…" }   // box = base64(iv 12 · tag 16 · AES-256-GCM(압축(JSON))) · aad = "pos|2.20"
// 풀면 — 현장 POS: { n, at, build, set: { 키: [바꾼 때 ms, 값] }, memo, mm: { su, u: { id: ms }, gone: { id: ms } }, acks: [{ id, ok, msg, t }], snap: 화면 | null, seen }
//        사무실 PC: { n, at, build, set, memo, mm, cmds: [{ id(12자리 16진), t, act, args }], open: true }
```
- 각 PC 앱 폴더 `desk-sync.json` = 설정 바꾼 때(meta) · 메모장 바꾼 때(mm) · 처리한 명령 id(done, 300개) · 연결 코드는 `settings.json` `syncCodeEnc`(Windows 암호화) · 역할 `syncRole`

# 두 PC 연결 — 현장 POS ↔ 사무실 PC (2026-11-06)

관리자는 사장님 한 사람이다. 운영 설정 · 근무자에게 남기는 메시지 · 판매 수량 자동조절 켜고 끄기는 근무자에게 시킬 수 없으니 **사무실에서 같은 버전의 통합데스크로** 하고, 그 결과가 현장 POS 에 그대로 적용되게 한다 (사장님 11/06).

**사장님이 정한 범위 (11/06 다시)**: 사무실 PC 와 우편함으로 주고받는 것은 ① 시계를 두 번 눌러 여는 **운영 설정 일체** ② **관리자 메시지**(메모장) ③ **자동 수량조절 켜고 끄기**(설정) ④ **키 현황** 뿐. 네이버 예약 · 고객 카드는 현장 POS 가 네이버에 넣은 결과를 **사무실 PC 가 네이버에서 직접 읽기만** 하면 된다 (조금 늦어도 됨). 주차는 사무실에 필요 없다.

## 어떻게 이어지나 — 고정 IP 없이 '우편함'
- 현장 POS · 사무실 PC 둘 다 고정 IP 가 없어 서로 직접 이어지지 않는다. 그래서 **두 PC 모두 바깥 우편함에 자기 문서 하나를 덮어쓰고 반대편 문서를 읽는다** (둘 다 밖으로 나가는 연결만 씀).
- 우편함 = **보고 시스템 클라우드**(설문 보고함 · 키즈 실시간과 같은 곳 · 같은 **보고 열쇠**): `boards/{보고 열쇠}/deskSync/pos`(현장 POS 가 씀) · `deskSync/office`(사무실 PC 가 씀).
- GitHub 를 우편함으로 쓰지 않은 까닭 (사장님 제안 11/06 을 검토): ① 바뀔 때마다 기록이 영구히 쌓임 — 예약 손님 · 네이버 상품 번호를 저장소에 넣지 않는 원칙과 맞지 않음 ② 현장 POS 에 쓰기 권한 토큰을 따로 넣어야 함 ③ 반영이 수십 초 ~ 분 늦을 수 있음. 보고 클라우드는 이미 연결돼 있고 문서 하나를 덮어써 기록이 쌓이지 않는다.
- **잠금**: 문서 안 내용은 **연결 코드**(현장 POS 가 만드는 16자리 · 예 `ABCD-EFGH-JKLM-NPQR`)로 잠근다 — 연결 코드 + 보고 열쇠 → scrypt → AES-256-GCM (압축 뒤). 보고 열쇠를 아는 사람도 내용을 읽거나 꾸며 넣지 못한다 (지우거나 덮어쓰면 연결만 끊김). 문서마다 '누가 · 어느 버전'을 함께 잠가 다른 자리로 옮겨 붙여도 안 풀린다.
- **같은 버전끼리만**: 두 PC 의 버전(ver.n)이 다르면 아무것도 반영하지 않고 양쪽 화면에 "버전이 달라요 — 현장 POS ver.x · 이 PC ver.y".
- 앱 본체 `apps/desk/src/desk-sync.js`(Electron 없이 시험) · 연결 `main.js` '두 PC 연결' · 화면 `prototype/desk.html` `syncSnap` · `syncApply` · `officeGate`.

## 주고받는 것
| 무엇 | 방향 | 규칙 |
|---|---|---|
| 운영 설정 (아래 '오감') | 양쪽 | 키마다 **늦게 바꾼 쪽**이 이김 · 처음 이을 때는 현장 POS 설정을 사무실 PC 가 받음 · 바꾼 때가 같은데 값이 다르면 현장 쪽 |
| 메모장 (근무자 · 내 메모 · 관리자 전달 · 접수 · 완료) | 양쪽 | 메모 · 전달마다 늦게 바꾼 쪽 · 지운 것은 양쪽에서 지움 · 근무자 목록은 늦게 바꾼 쪽 |
| 키 현황 | 현장 → 사무실 | **사무실 PC 가 켜져 있을 때만** 바뀌면 2초 안 · 사무실이 꺼지면(2분 30초 소식 없음) 안 올림 |

- **오가는 설정**: 성수기 기간 · 판매 수량 자동조절(켜고 끄기 · 목표 · 순위 · 맨 위 [오늘 수량조절]) · 입금대기 자동 취소 · 재고 자동 오픈 · 입장권 양식 · 프린트물 설정 · BC 양식 · 재방문 이벤트 · 현장 이벤트 · 설문 · 폰 실시간 현황 켜짐 (`desk-sync.js SHARED`)
- **키 현황** = 입장한 네이버 예약의 열쇠 번호 · 입장 · 반납 시각 · 이용시간 · 연속예약 (예약번호로 사무실 PC 가 읽은 네이버 카드에 붙임) + 현장 입장 · 서비스 키의 열쇠 + 옮긴 카드 시간 · 시험 기록 삭제 · 골든벨. **이름 · 전화번호 · 손님 메모는 빼고** 보낸다 — 열쇠판의 이름은 사무실 PC 가 읽은 네이버 카드에서. 사무실 네이버에 아직 없는 입장은 '예약 손님'으로 보이다가 사무실이 네이버를 다시 읽으면 그 카드로
- **안 오감**: 네이버 예약 · 고객 카드(사무실 PC 가 네이버에서 직접) · 주차 · 프린터(포트 · 속도 · 현금통) · API(아마노 · 톡톡 · 네이버 주소) · 보고 열쇠 · 쿠폰 봉인 열쇠 · 방문 기록 · 이벤트 장부 · **고객 세부 관리(손님 메모 · BC · 마일리지 SKIP)** → 사무실 PC 카드에는 손님 메모 · BC · 재방문 이벤트 표시가 없음

## 사무실 PC 에서 되는 것 · 안 되는 것
- **됨**: 키 현황 보기(열쇠판 · 열쇠 창) · **네이버 예약 보기**(이 PC 가 직접 — [새로고침] · 날짜 넘기기 · 시간 칸 · 자동 불러오기 때) · 운영 설정 일체(각 PC 것 빼고) · 메모장(관리자 전달 · 메모) · 맨 위 [오늘 수량조절] · 네이버 설정의 자동조절 켜고 끄기
- **막힘 (현장 POS 에서만)**: 네이버에 넣는 일(이용완료 · 판매 수량 [지금 조절] · [한 칸 시험] · 입금대기 취소 · BC 취소 · 재고 [확인만] · [지금 한 번]) · 입장 · 반납 · 결제 · 초과요금 · 서비스 키 · 이벤트 입장 · 열쇠 옮기기 · 출력 · 주차 · 톡톡 · 고객 BC · 보고 보내기 · 지난 방문 기록 읽기 → "사무실 PC — 이 일은 현장 POS 에서 해요" (앱 본체도 사무실 PC 의 이용완료 · 판매 수량 · 취소 · 재고 · 지난 기록 읽기를 거절)
- 사무실 PC 는 **네이버 창만** 연다 (아마노 · 톡톡 · POS · 현금통 · 프린터 도우미 없음) · 처음 한 번 사무실 PC 에서 네이버 로그인(운영 설정 → API 연결 설정 → 네이버 화면 보기) · 보고(설문 · 실시간 · 재방문 · 이벤트)를 보내지 않고 오늘 기록 파일도 안 씀
- 맨 위 작은 표시: 사무실 PC = "사무실 PC · 키 현황 14:05 기준" (3분 넘게 소식이 없으면 "키 현황 n분째 소식 없음" · 버전 다름 · 연결 코드 확인) / 현장 POS = 사무실이 보고 있으면 "사무실 PC 연결됨" · 오류면 "두 PC 연결 확인"

## 처음 잇는 법 (사장님 한 번)
1. **보고 시스템 규칙에 `deskSync` 더하기** — 아래 '보고 시스템이 할 일' → Firebase 콘솔 → Firestore Database → 규칙에 붙여 넣고 [게시] (키즈 실시간 때와 같음). 게시 전에는 상태에 "열쇠나 모양이 틀림 (403) — 보고 시스템 규칙에 deskSync 가 있는지"
2. **현장 POS**: 운영 설정(시계 두 번) → **두 PC 연결** → 이 PC 역할 **[현장 POS (본 PC)]** → [지금 다시 켜기] → 연결 코드 16자리가 보임 (보고 열쇠는 기타 → 보고 앱에 이미 있음)
3. **사무실 PC**: 같은 버전 설치 파일로 설치 → 운영 설정 → 기타 → 보고 앱 **보고 열쇠**(현장과 같은 것) → 두 PC 연결 → **[사무실 PC]** → 연결 코드 넣고 [저장] → [지금 다시 켜기] → API 연결 설정에서 **네이버 화면 보기 → 로그인**(처음 한 번 · 예약현황 화면에서 [지금 화면을 시작 화면으로])
4. 15초 안에 사무실 PC 맨 위 "사무실 PC · 키 현황 hh:mm 기준", 현장 POS 맨 위 "사무실 PC 연결됨"
- 새 버전을 낼 때는 **두 PC 모두** 같은 설치 파일로 (한쪽만 바꾸면 "버전이 달라요" — 그동안 사무실 PC 는 반영 없음, 현장 POS 는 평소대로 동작)
- 연결 코드를 새로 만들면(현장 [새 코드 만들기]) 사무실 PC 에도 다시 넣는다 · 역할을 [안 씀]으로 하면 그 PC 는 예전처럼 혼자

## 우편함 쓰기 · 읽기 수 (Firestore 무료 한도: 하루 쓰기 2만 · 읽기 5만)
- 현장 POS: 사무실이 꺼져 있으면 15초마다 읽기 1(하루 영업 12시간 ≈ 2,900) · 쓰기는 설정 · 메모장이 바뀔 때만
- 사무실 PC 가 켜져 있는 동안: 양쪽 4초마다 읽기(시간당 900 × 2) · 현장 쓰기 = 키 현황이 바뀔 때(3초 간격) + 1분마다 · 사무실 쓰기 = 1분마다 + 바꿀 때
- 예) 사무실 PC 를 하루 8시간 켜 두면 읽기 약 1만 7천 · 쓰기 수천 — 키즈 실시간(1분마다 쓰기)과 합쳐도 무료 한도 안
- 사무실 PC 의 네이버 읽기는 우편함과 상관없음 (현장 POS 와 같은 때 · [새로고침])

## 보고 시스템이 할 일 (gnb21c-cmd/report — 규칙 한 덩어리)
`firebase/firestore.rules` 의 `match /boards/{board} { … }` 안, `deskStats` 아래에 더함:
```
      // 두 PC 연결 (통합데스크 현장 POS ↔ 사무실 PC · 2026-11-06) — astanakiz docs/SYNC.md
      //   문서 둘(pos · office)만 계속 덮어씀 · json = 잠긴 글(astanakiz-sync · 연결 코드 없이는 못 읽음) · 보고 앱은 읽지 않음
      match /deskSync/{doc} {
        allow read: if true;
        allow create, update: if (doc == "pos" || doc == "office")
          && exists(/databases/$(database)/documents/boards/$(board)/settings/main)
          && request.resource.data.keys().hasOnly(["json", "at"])
          && request.resource.data.json is string && request.resource.data.json.size() < 900000
          && request.resource.data.json.matches("(?s)^[{].*astanakiz-sync.*$")
          && request.resource.data.at is string && request.resource.data.at.size() < 40;
        allow delete: if isSender(board);
      }
```
- 확인할 것 (에뮬레이터): `pos` · `office` 만들기 · 고치기 · 읽기는 됨 / 다른 이름 · 설정 없는 열쇠 · 다른 칸 · `astanakiz-sync` 아닌 글 · 큰 글 · 로그인 없는 지우기는 막힘
- 읽기(통합데스크가 함): `GET …/documents/boards/{열쇠}/deskSync/{pos|office}` → `fields.json.stringValue` (없으면 404 = 아직 안 씀)
- 보고 앱 화면은 바꿀 것 없음

## 문서 모양 (`deskSync/{pos|office}` 의 `json`)
```jsonc
{ "type": "astanakiz-sync", "v": 1, "role": "pos", "build": "2.20", "n": 128, "at": "2026-11-06 14:05:12",
  "box": "…" }   // box = base64(iv 12 · tag 16 · AES-256-GCM(압축(JSON))) · aad = "pos|2.20"
// 풀면 — 현장 POS: { n, at, build, set: { 키: [바꾼 때 ms, 값] }, memo, mm: { su, u: { id: ms }, gone: { id: ms } }, acks: [], snap: 키 현황 | null, seen }
//        사무실 PC: { n, at, build, set, memo, mm, cmds: [], open: true }
// 키 현황 snap = { v: 2, day, at, b: [입장한 예약 { id, no, slot, naverSlot, qty, product, naverProduct, status, keys, enteredAt, outAt, overPaid, useMin, keyUse, chainHead, keysTaken, bulkOut, visitEnd, naverPending, naverWhy }],
//                  w: 현장 입장(전화번호 뺌), s: 서비스 키(이름 · 전화 · 연결 손님 이름 뺌), x: 시험 기록 삭제, ig, mv: 옮긴 카드 시간, g: 골든벨,
//                  r: 대관 [{ id, name: 단체 이름, paidOn: 입금일 }] (다음 판~ · 사무실은 보기만) }
```
- 명령 통로(cmds · acks)는 앱 본체에 있으나 이 버전 화면은 쓰지 않음 (사무실은 네이버에 넣지 않음 — 사장님 11/06)
- 각 PC 앱 폴더 `desk-sync.json` = 설정 바꾼 때(meta) · 메모장 바꾼 때(mm) · 처리한 명령 id(done) · 연결 코드는 `settings.json` `syncCodeEnc`(Windows 암호화) · 역할 `syncRole`
